# Agent 工作监控 1.3.0

## 工作现场界面（2026-10-10）

浅色 Mac 风格工作台：顶部概况、任务搜索与分片/状态筛选、当前动作、信号/活动时间、执行时间线和事件来源筛选。两秒轮询真实接口，保留列表与时间线节点，仅新事件高亮；断线保留快照、禁用控制并自动重连。已断线、已结束及尚未接入控制检查点的任务不提供暂停操作。零计数与未上报分别展示，结束状态不代替业务回执。

概况基于接口最近 40 次记录：正在执行包含在线无新步骤；需要关注包含停顿、信号中断、暂停、失败和中断，含历史记录；今日执行结束按上海时区的最终活动日期统计。未知执行状态不计为运行中，不覆盖所有本机 Codex 会话。

验证：`python3.12 -m unittest test_monitor test_desktop_observer -q`；`node test_frontend.cjs`。前端测试使用隔离 DOM/API，不操作真实任务。

本机入口：`http://127.0.0.1:8796`。A/B 启动器每次运行自动唤醒服务；页面可一直打开，每两秒刷新。支持并发分片、当前动作、最近业务群/消息/文件、流水线阶段、已送审与未过数量、事件时间线、暂停与继续。

程序检查点是实际状态机事件；执行器事件来自工具开始/结束；Agent 主动上报是自身声明，不等于业务校验。最近业务对象可能与最新工具事件不同，界面明确标为“最近”。未知计数不显示为零。任务结束不代表已正式入库。心跳只证明执行器活着；45 秒无信号提示中断，180 秒无新动作提示暂无新步骤，不推断业务失败。

暂停在下一次 `pipeline.py next/advance` 或 `monitor.py report` 开始时等待，不中断在途命令与数据库请求；暂停可能跨越当前一整个命令。不杀 Agent，也不自动重跑任务。监控不可达时告警并继续采集。

## 接入

启动入口 `run_agent.py` 继承现有模型、权限、目录、日志与最终回执位置，改用结构化执行事件；向子进程注入 `FRT_MONITOR_RUN_ID`。额外业务细节由 A/B prompt 要求逐群、逐图、逐消息上报：

`python ops/agent-monitor/monitor.py report --stage OCR --activity "核对价卡底部港口定义" --group "实际群名" --message-id "实际ID" --file "实际图片名"`

只带已知字段。通用外部 Agent 也可设置运行 ID 后调用同一入口；本版自动挂接范围是本项目 A/B 定时采集，不声称覆盖所有 Codex 会话。

## 架构与数据

`agent_watch/core/contracts.py` 定义类型和接口常量，`services/progress.py` 只做校验、脱敏和展示状态推导，`transport/` 负责本机 HTTP、进度数据库、客户端。仅标准库。监控数据库位于 `runtime/monitor.sqlite3`，与业务数据库完全独立。每个任务保留最近 250 条细节，首页显示最近 40 次；当前任务状态保留。

服务仅绑定 127.0.0.1。上报需要本机自动生成的凭据文件；浏览器控制需要同源请求和 HttpOnly 会话，不输出密钥。拒绝跨站控制。面板不接收原始消息正文、工具输出或完整命令行。运行 ID、群、文件和业务消息 ID 是定位信息；不适合把此端口直接开放公网。

`FRT_MONITOR_URL` 可覆写客户端地址，仅用于本机隔离测试或同接口服务；默认 8796。服务测试可用 `transport.server.serve(runtime, web, port)` 指定隔离目录和端口。


## 应用内入口修正

当前上午B实际走Codex应用内cron，Windows任务禁用不代表采集停止。本服务新增本项目四个应用内采集会话的只读观察，按原始事件时间补接当前任务；工具事件持续增量显示。任务名直接显示原名称；内部审批会话、其他项目和其他自动化不显示，不转发推理、消息正文或工具输出。

pipeline自动以CODEX_THREAD_ID/CODEX_SESSION_ID对齐desktop运行身份并自动唤醒；主动report同样识别桌面身份。观察器尚未得到pipeline的control_ready确认时，界面只观察，不宣称暂停有效。上午B实际自动化已加入开工wake，保留原时刻、模型、通知策略。应用内任务完成以真实task_complete事件显示；执行完成仍不表示业务报价全通过。
