# 解析质量优化方案 v3（2026-10-08，第二轮修订）

> 本版吸收第二轮评审意见：修正金额比对口径、消息意图判断、柜型推断证据、via 处理、主数据补齐边界。
> 原则不变：宁可待审、不误入库；自动放行不允许；不猜值、不造绝对成本。

## 执行顺序（按优先级，3 大步）

**落地顺序**：先防错误报价入库 → 再检查漏港漏价 → 最后补主数据。
这样提高的是准确性，不只是"通过率"。

---

## 第一步：防错误报价入库（最高优先级）

### 1. 消息意图分类（防询价/操作通知被复制成报价）

**问题**：v2 的"被引用是询价 → 不产"太绝对——销售问价后，航管回复真实价格，也会被过滤掉。

**修正**：以**当前消息的行为**判断，不是以被引用消息判断：

| 当前消息特征 | 判定 | 处理 |
|---|---|---|
| 有明确金额 + 价格表/报价格式 | 报价 | 正常入库 |
| 有金额但在问句里（"2800 能接吗"、"3100 还能做吗"） | 询价 | 不产新报价，标"询价" |
| 无金额 + 问价/能走吗/还有吗 | 询价 | 不产新报价，标"询价" |
| 开舱/截关/催单/放舱/@人 | 操作通知 | 不产报价 |
| 引用报价 + 本条是调价（"降 200"、"改 3100"） | 调价 | 标已覆盖，不产新行 |
| 引用报价 + 本条是问（"还有吗"、"能接吗"） | 询价 | 不产新报价 |

**关键修正**：
- ✅ 被引用是报价，本条是航管回复真实价格 → 正常入库（不是询价）
- ✅ "2800 能接吗" 有金额但仍是询价（问句格式）
- ❌ 不再"被引用是询价 → 不产"一刀切

**判定特征**写进 extraction-rules（询价动词清单、操作通知动词清单、问句格式正则）。

### 2. 确定性拆分：柜型配价 + 多港拆行（按证据推，不硬套）

**问题**：三段数字默认对应三种柜型，仍可能把重复的 40HQ/HC 价格误当成 NOR。

**修正**：柜型配价必须有证据支持，不硬套三档：

**柜型配价证据优先级**（从高到低）：
1. **图片表头**：明确写了 "20'/40'/40NOR" 或类似 → 按表头列对应
2. **文字明确**："20GP 2800 / 40HQ 3600 / 40NOR 3800" → 按文字对应
3. **群/发布人知识**：该群/该发布人通常只报两档（如韩琦价卡 A/B/B）→ 按两档配
4. **三段数字 + 上下文支持三档** → 逐档配价
5. **无法确定** → 保留原文，不猜、不造，标"柜型未确定"

**关键修正**：
- ❌ 不再"三段数字 → 自动对应 20GP/40HQ/40NOR"
- ✅ 先看表头、看文字、看群惯例，没有证据不硬套第三档
- ✅ 数字重复（如 2800/3600/3600）不自动认为第三档是 NOR，要标"疑似 NOR 但无证据"

**多港拆行**：
- `/`、`、`、`,` 分隔的并列港 → 确定性拆行（同价共用）
- `港名,国家` 不拆（如 "Santos, Brazil"）
- **via 处理修正**：`via` 走法**不并入目的港字符串**——目的港只放港口；走法放现有"航线服务"字段或备注

**附加费拆分**：PCS/ISPS/EFS 等 → 备注；海运费永远裸价。

### 3. 证据冲突处理（不统一"表头优先"）

**问题**：v2 的"冲突统一表头优先"太绝对——新消息的调价说明可能被旧图片表头覆盖。

**修正**：判断消息时间和适用范围：

| 情况 | 处理 |
|---|---|
| 正文写"本周降 200" + 旧图片表头是原价 | 按正文（新消息的调价） |
| 正文写"参考价" + 图片表头是报价 | 按图片表头（正式报价） |
| 无法判断哪边是最新/正式 | 标"证据冲突"，保留两处原文，不自动选 |

**关键修正**：
- ❌ 不再统一"表头优先"
- ✅ 判断消息时间（哪个是新的）和适用范围（哪个是正式报价）
- ✅ 不能确定才保留冲突，让人工判断

## 第二步：检查漏港漏价

### 4. 金额清单回读校验（修正口径）

**问题**：v2 的"图上金额 vs 生成记录金额集合比对"太粗糙——附加费会被误判为漏价；多个港口价格一样时，漏港也查不出来。

**修正**：按**维度逐项核对**，不能只比较金额集合：

| 维度 | 说明 |
|---|---|
| 起运港 | 图上提到的所有起运港 |
| 目的港 | 图上提到的所有目的港 |
| 柜型 | 图上提到的所有柜型 |
| 金额 | 对应柜型的裸价 |
| 费用类型 | 海运费 / 附加费 / 免箱期天数等 |

**回读校验逻辑**：
1. `amount_list` 记录图上所有金额，附带对应港口/柜型/费用类型（不是裸金额列表）
2. 比对：图上的每个 (港口, 柜型, 费用类型) 组合，是否都对应到了生成记录
3. 漏了 → 标"本图另有 N 个组合未生成记录"，写明是哪个港口/柜型/费用类型

**关键修正**：
- ✅ 按 (港口, 柜型, 费用类型) 逐项核对，不是只比较金额数字
- ✅ 附加费不算漏价（它在备注里），只核对海运费裸价
- ✅ 多个港口价格一样也能查出来漏港（因为港口维度不同）

### 5. 历史恢复器：接入常规定时采集的同一套机制

**修正**：历史恢复器（backfill）接入同一套回执/清单/回读机制，不允许两套标准。

- `ocr_cache/<mediaId>.json` 增加完成回执：`receipt = {status: complete|partial|failed, reason, total_rows, extracted_amounts}`
- 识读结果含原图金额清单 `amount_list`：图上所有金额原样列出，附带对应港口/柜型/费用类型
- pipeline 在 BUILD 前对 cache 做回读校验

## 第三步：补主数据（最后做，先核实再补）

### 6. 港口代码匹配（先修索引，再补港口）

**问题**：v2 的港口补齐名单里有未确认名称（Chung Nia 等识读疑点），可能变成错误主数据。

**修正**：先修标准码匹配入口，再补真正缺失的港口：

**第一步：修 locode_ref 入口**
- locode_ref 目前没有进入港口匹配索引 → 先修这个入口
- 避免已有港口被当成缺失而重复创建

**第二步：核对已有港口**
- TST：已对应青岛（船司代码语境）→ 不再作为缺失港口
- Freeport Bahamas：已有处理 → 不再作为全新港口
- 其他已登记的港口先核对一遍，不要重复补

**第三步：补真正缺失的港口**（必须先核实原图，确认不是识读错误）
- Danang(VN) / Quinhon(VN) / Semarang(ID) / Manila North(PH) / Kuala Tanjung(ID) / Subic Bay(PH) / Yokkaichi(JP) / Alicante(ES) / Bejaia(DZ)
- ❌ Chung Nia 等识读疑点 → 先核实原图，确认不是 OCR 错误再补
- 内部码按证据登记：YAT→Yantian、SGH→Shanghai、NPO→Ningbo、YOK→Yokohama、BUS→Busan 人工确认后登 `alias_scope`

**未知码保留原值 + 失败原因**：不命中主数据的港口字段保留原文不清空，errors/备注写明 `未命中主数据：<码>，疑似<上下文>，待人工确认`。

### 7. 港群补齐（必须有明确成员）

**问题**：v2 的"Spain BP→西班牙基本港"太笼统——BP 港群必须有明确成员和适用范围，不能直接等同于某国全部港口。

**修正**：
- BP 港群必须有明确成员清单（如 Spain BP 成员：Almeria/Barcelona/Valencia/Bilbao/...）
- 适用范围（哪些群/哪些发布人用这个港群名）
- 业务确认后才登记 port_groups

## 验收样例（修正版）

### 正向验收：正确报价能拆齐

**样例**：某报价消息，图上写 "CMA 上海 → 欧洲基本港 20GP 1900 / 40HQ 3100"
- 预期：2 条记录（20GP 1900、40HQ 3100），不漏行不丢价

### 反向验收：不能造报价

**样例 1（询价）**：土耳其群消息 "第 41 周好放不？"
- 预期：0 条新报价（这是询价，不是报价）
- ❌ 不再写成 "7 港 × 3 柜型＝21 条"——因为这条消息本身是询价，不产新报价
- 它引用的原报价有 7 个起运港、8 个目的港，那是被引用消息的内容，不是本条要产的

**样例 2（公式）**："表价 - 600 + EBS 400"
- 预期：价格留空 + 公式进备注 + 证据状态=成本未确定
- ❌ 不自动算裸价

**样例 3（幂等）**：同一条消息重跑
- 预期：不产生重复记录

## 保留与修正（v2 已有的，保留）

### 空字段回看（保留，细化证据状态）

"空字段必须回看证据"保留，但备注区分证据状态，禁止统一写"图文均确认无此字段"：

| 状态 | 含义 | 备注模板 |
|---|---|---|
| 确实未写 | 原文/图均无此字段 | `空字段-确实未写：<字段>` |
| 画面截断 | 图截断导致看不到 | `空字段-画面截断：<字段>，图顶部/底部截断` |
| 无法辨认 | 图有但识图无法辨认 | `空字段-无法辨认：<字段>，OCR 不清` |
| 成本未确定 | 只有成本公式、无确定裸价 | `空字段-成本未确定：<字段>，公式=<原样>` |
| 证据冲突 | 多处证据矛盾 | `空字段-证据冲突：<字段>，两说=<a>/<b>` |
