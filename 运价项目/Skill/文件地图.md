# 心跳 skill 文件地图

`freight-rate-heartbeat` 包 33 个文件（约 49K 字），加包外运行态 1 份。
读这份地图的三种人：换机器接手的人、被叫来跑一轮的 Agent、想改口径的你自己。

**一句话定位**：拉钉钉群消息 → 模板/LLM 判定 → 只写台账 `/api/pending` → 人工在看板放行。
**包外三层**别混：`freight-rate-heartbeat/` 是技能包（会被安装/加载），`heartbeat-data/` 是运行态（不进包不进 git），
`../Database/` 是台账（值域与放行的真闸门）。

## 1. 包内结构（谁读它 / 改了会怎样）

```
freight-rate-heartbeat/
├─ SKILL.md                     Agent 入口。frontmatter 的 description 决定这个包会不会被唤起
├─ Instruction.md               人读总览：跑法、边界、为什么这么设计（41 行）
├─ references/                  ← Agent 判定前读的东西（人也可以直接看）
│  ├─ extraction-rules.md       全局口径 25 条。rule_basis 里的 #N 就是这里的条款号
│  ├─ runbook.md                每轮操作顺序：水位拉取 → 落盘 → 识图 → 提交
│  ├─ learnings.md              事故与纠错记录。开工先读；被纠错当场追加一条带日期的
│  ├─ data-review.md            数据审查口径（哪些值算脏、怎么判）
│  ├─ Instruction.md            references 目录自己的导航
│  └─ 群聊规范/
│     ├─ README.md              目录↔群↔slug + 检索规则（"列+群"作用域、待补不许猜）
│     └─ <群名>/规范.md          13 份：定位/报价格式/缩写表/已知坑/解析要求/别名登记日志
└─ scripts/                     ← 机器执行的东西
   ├─ paths.py                  路径单一真源（PROJECT_ROOT / RUNTIME_DIR / WORK / OCR_CACHE）
   ├─ watermark.py              水位线读写（决定"从哪条消息接着拉"）
   ├─ record_builder.py         模板直出中文键记录（命中即 0 LLM）+ vdates/compose_text
   ├─ validity_parser.py        有效期解析唯一口径（禁止各处自写正则）
   ├─ pipeline.py               状态机主控：next / advance（PULL→PARSE→LLM_PENDING→BUILD→SUBMIT）
   ├─ ledger_client.py          台账 HTTP 层：validate / submit / master，唯一写入口
   ├─ spec_index.py             🆕 群规范机器入口：slug→规范文件、缩写表、「待补」条目、锚点解析
   ├─ check_llm_out.py          🆕 判定文件只读自查：溯源 / 禁填键 / 枚举 / rule_basis 真伪
   ├─ spec_alias_diff.py        🆕 规范缩写表 ↔ 台账 alias_scope 差集 + 断链体检
   ├─ llm_output_contract.md    LLM 输出契约（含 rule_basis 写法与自查命令）
   ├─ Instruction.md            scripts 目录导航
   └─ config/
      ├─ chat_sources.json      13 群：cid / name / slug / **spec_dir** / default_pol / profile
      ├─ ledger_contract.json   柜型三档、舱位十一档、台账连接参数、runtime_dir
      └─ Instruction.md         配置字段说明 + "枚举三处必须对齐"的要求
```

## 2. 按"谁能改"分

| 层 | 谁能改 | 改完必须做什么 |
|---|---|---|
| `scripts/*.py`、`config/*.json` | 人工（Agent 别擅改） | 跑 `python ../../test_spec_layer.py` + 源→运行同步 |
| `references/extraction-rules.md`、`群聊规范/*/规范.md` 的坑与缩写 | Agent 可**追加**，人工修订 | 同步 alias_scope（台账放行候选会自动回写"别名登记日志"） |
| `learnings.md` | Agent 被纠错当场追加 | 无 |
| `heartbeat-data/watermark.json` | 只有 `watermark.py` 写 | **手改＝重拉历史或漏消息**，别碰 |
| `heartbeat-data/.work/` | 每轮产物 | 可整个删，下轮重建（`msgs_/draft_/llm_out_/ocr_cache_`） |

## 3. 现在这条链上有四道机械关卡（2026-09-17 补齐）

```
chat_sources.spec_dir ──→ spec_index 路由 ──→ llm_queue 每项带 spec_path + spec_todo   ①
      Agent 读该群规范判定，写 llm_out（rule_basis 必须是真实锚点）
pipeline advance 前 ──→ check_llm_out 反查锚点 / 禁填键 / 枚举 / 逐档配价              ②
POST /api/pending ──→ 台账闸门：必填、主数据命中、合并船司拆分、柜型贪婪匹配、AI判断     ③
manual_check.py ──→ spec_alias_diff：规范缩写表 ↔ alias_scope 差集 + 断链             ④
```

①②④ 只管"规范有没有被执行、两边是否漂移"，**只报告不拦**；值域的硬拦在 ③（台账），因为它是唯一事实源。

## 4. 三份"真源"别再复制

- **路径**只在 `paths.py`；配置里 `project_root`/`runtime_dir` 可覆盖，env `FRT_*` 优先。
- **枚举**三处必须一致：`manualdb.SPACE_TYPE_ENUM` ↔ `ledger_contract.space_type_options` ↔ `web/index.html` 的舱位类型选项（柜型同理）。改一处就要三处改，`manual_check` 会撞出来。
- **别名**真源是台账 `alias_scope` 表；`规范.md` 的缩写表是人读来源，漂移由 ④ 报出来（今天实测：规范 54 行、库里 37 行，待登记 1 条 `欧洲价格更新/pol/+TAO→Qingdao`、库里未写 2 条）。

## 5. 两份副本必须一致

`~/.qwenworkcn/skills/freight-rate-heartbeat/` 是运行副本（cron 与 Agent 实际加载它）。
**改完源必须同步过去**，否则定时任务读到的是旧世代。校验：两边同名文件 md5 一致（本轮同步 10 个文件，全一致）。
