# 微调规则（用户口径，必须遵守）

> 从 SKILL.md 移出的完整细则。判定入库前按需查阅，不必全文进上下文。
> record_builder.py 已内置其中可编码的规则（柜型三档、附加费进备注、有效期解析、无金额港点跳过）；
> 本文件用于 LLM 复核 med/high 置信度记录和模板未命中消息时的口径依据。

> ⚠️ **2026-09-10 台账化改版**：入库对象是「运价台账」`POST /api/pending`。**字段中文名、枚举合法值、核心字段必须命中主数据、价格整数、有效期 ISO、消息时间必带**等口径以 `Database/docs/agent-input-contract.md` 为唯一权威；下文第 3 条已按台账改写。抽取与判定口径（柜型三档、有效期解析、引用回复、原文逐字、附加费进备注等）仍然适用。柜型/舱位类型枚举台账不兜底，`pipeline.py` 自守；主数据缺口（华南基本港等）见 `references/learnings.md` 待观察。

1. **起运港三级判定**：① 消息正文明示的港口优先（SHEKOU→蛇口、YANTIAN→盐田、XINGANG→天津新港、NINGBO→宁波、QINGDAO→青岛、NANSHA→南沙）；② 否则取群名中的地名；③ 群名无地名则统一填 `华南基本港`。COSCO 那种"全口岸"列表照原样写入，别压缩成单个港。**注意**：台账核心字段必须命中主数据，`华南基本港` 这类语义港群需已在台账 `port_groups` 登记，否则相关记录会以 `failed` 进待审核（见 `learnings.md` 待观察）。
2. **航线分类**：沿用工作台口径（欧基港/地东/地西/北非/黑海/亚德里海/希腊/中东/东南亚/美西/美东）+ 已扩展的 `加勒比`/`南美东`/`南美西`/`墨西哥`/`中美洲`。**台账里 `航线` 填了必须命中 `routes` 主数据（可空）**——拿不准就留空让人工在台账「主数据库→航线」补登记后再放行，别自造航线名硬塞（会被判 failed）。
3. **同航线同有效期只认最新一条，旧价不删除、不就地改写**：群里常在几小时内连续更新同一份报价（如 10:00 发 HMM 南美东、16:43 又补两条船；14:45 发 CMA 9.8-9.14、16:39 标"更新"换图）。因此：
   - 入库前必须把**整个时间窗**（当天 00:00 至当前时刻）的消息全部拉完，不能边拉边入
   - 按 `航线 + 有效期 + 船司` 分组，组内取 `createTime` 最大的那条作为**当前事实源**
   - **agent 只产新记录，不改旧行、不写任何状态回写字段**。改价/售罄一律由 LLM **产出新记录（insert）**；旧行不动，"当前价"由台账折叠视图 `fold` 现算（`/api/rates_grouped` 每组默认展示当前、其余进历史）
   - 台账对**同 `起运港+目的港+船司+原文`** 的提交会自动判"更新（留痕）"而非堆重复行——所以同一条报价重发不会产生脏数据，`消息原文` 逐字尤其重要
   - 若旧消息含新消息没有的港点（如补充航次），合并两者港点集合，但价格以最新为准
   - 判定"是否同一条"要同 `来源群`（跨群转发各存一份，互不覆盖）且有效期/船期口径一致；同一港口不同船期（9.5 船 vs 9.8 船）是两个航次，都算当前生效，不是覆盖
4. **柜型只有三档，写死不可扩展**：`20GP`、`40HQ/HC`、`40NOR`。
   - `小` / `20'` / `20GP` / `20DC` → `20GP`
   - `高` / `40'` / `40GP` / `40HQ` / `40HC` / `40'GP` / `40'HC` / `40GP/40HC` → **一律合并为 `40HQ/HC`**（报价表里 40GP 与 40HC 同价，所以并成一档，不分开存）
   -  `NOR` / `40NOR` / `40'NOR` → `40NOR`
   - 三段报价串 `7708/7908/7908` 按 `20GP` / `40HQ/HC` / `40NOR` 拆时**只产生三条**（中间两档同价，合并成一条 `40HQ/HC`）
   - 只有两段且未注明柜型（如 `6600/6500`）→ `20GP` + `40HQ/HC`
   - 若某张表 40GP 与 40HC **确实不同价**，不要擅自合并：保留两条并在备注标注"40GP/40HC 不同价，需人工确认柜型口径"
5. **停接/无报价港口不入库**：表中标 `/`、`N/A`、`SUSPEND`、`case by case`（即拿不到金额）的港口直接跳过，不产生空价格记录。但**标红写"停接"且仍有价格**的港口要入库，并在备注**开头**标注 `停接（暂停接载）；` 便于筛除。
6. **跨群重复不去重**：同一条报价被转发到多个群时，每个群各存一份，保留"哪个群发的"这个粒度。不要按内容指纹合并。
7. **只入运价，不入动态**：现舱/配额/箱子开舱/截数据通知/操作提醒/@人催单类消息一律不入运价表。但"指导卖价""成本价""合约价"这类带报价的即便挂在现舱消息里也要入。判定看**有没有金额**：`9.6 特价合约 CALLAO 多出一个NOR现舱，价格超低` 无价→不入；`msk线上现舱 QINGDAO-COBUN 5X40HQ 9.5，15 天ft，USD6887` 有价→入。
8. **有效期冲突**：以图片表头为准入库，并在备注里注明两说（如"表头有效期9.8-9.14，消息正文写9.7-9.14"）。
9. **有效期必须解析成日期列**：`有效期船期` 保留原文自由文本用于展示与溯源，同时必须解析出结构化列，否则做不了过期灰显和跨周涨价对比。统一调用 `scripts/validity_parser.py` 的 `parse(text, msg_date)`，禁止各处自己写正则，避免口径漂移。三类情况：
   - **区间型**（`9.1-9.7`、`9/1-9/7`、`9.1~9.7`、`9.1-14`、`2026/09/01~09/07`、`1 Sep - 7 Sep`）→ 填 `有效期起` + `有效期止`，`船期ETD` 留空
   - **单开船型**（`9/7开`、`9.12 ETD`、`ETD：9.8`、`8.31托9.8`、`9/6晚开9/9`、`ETD SHEKOU 6/SEP`）→ 只填 `船期ETD`（取开船那个日期，`晚开`取前一个），`有效期起/止` 留空。这类没有有效期，不要拿开船日硬凑成区间
   - **不可解析**（`case by case`、`锁8月底运价+500`、空）→ 三列全留空，原文照抄进 `有效期船期`
   - **年份推断**：默认取消息所在年份；若解析出 `起月 > 止月` 说明跨年，`止` 年份 +1；若 `起` 月份比消息月份大超过 6 个月，视为上一年（跨年回卷）
   - **GRI 不是有效期**：`9.08 GRI 1,000/1,000/1,000` 是综合费率上调生效日，写进备注，不要解析成有效期
   - **展示文本与解析输入可以不同**：`有效期船期` 照抄群里怎么写的（`9.8-14`），但若这句解析不出来，用 `add(vparse=...)` 传图内表头原文（`Validity 8 SEP- 14 SEP 2026`）给解析器。只允许"补全"，不允许改数
   - **归一化例外**（record_builder.py norm_v 已内置）：`9/8--9/14` 双横线先归一为单横线；`9.6晚9.8` 补成 `9.6晚开9.8`；`8-Sep to 14-Sep` 补成 `8 Sep - 14 Sep 2026`
   - 配套视图：在表格里建视图对 `有效期止` 加条件格式（早于今天→灰底），并按 `起运港+目的港+柜型+船司` 分组、`有效期起` 排序，即可看同一条线的涨价 diff
10. **附加费归备注**：PCTS/PCS/EFS/FAF/碳排放/GFS/危险品PG分级/重量附加/内陆费 add on 等全部写进备注，**不要**加到海运费数字上，海运费永远保持原报价裸价。
11. **只有加价公式、没有绝对金额的港点**：如宁波 CMA 表里 `MAR DEL PLATA:+900/BOX on top of ECSA BP`、`PYASU add on +1000/1200/1200 on top of ECSA BP`。这类**保留记录但 `海运费USD` 与 `柜型` 留空**，把公式原样抄进备注（注明"在ECSA BP基础上另加"）。**禁止**自己拿基价加出绝对价——基价一改，派生价就成了假数。
12. **消息原文必须逐字全文（引用回复附带被引用原文）**：`消息原文` 字段直接取 `dws chat message list` 返回的 `content`，**原样照抄**——保留 `@所有人`、换行 `\n`、加粗星号、删除线 `~~…~~`、emoji、中英文标点、多余空格。严禁用 `|`、`…`、省略号压缩，严禁改写、润色、重排或只摘关键句。若这条是引用回复，`消息原文` 由 `record_builder.compose_text()` 装配为「本条全文 + 一行 `——引用 <时间> <发送人> mID=<被引用消息ID>——` + 被引用消息全文」，两段都保持逐字、不改写。同一条消息派生的所有记录，其 `消息原文` 必须完全一致（拼法确定，可作台账新增/更新判定与内容指纹的稳定键）。落地做法：一律从 `.work/msgs_*/<slug>.json` 的 `c`/`q` 反查，生成器里手打原文即视为违规。
13. **溯源完整性**：每条记录必须带 来源群+发送人+消息时间+消息原文（全文）+运价原图。纯文字报价无图时，附件字段留空即可。
14. **合并港点**：一行覆盖多个港（如 `CAUCEDO/KINGSTON/CARTAGENA`）时按原样保留为一个目的港字符串，不拆成多条，避免造出报价里并不存在的独立价。同一基本港因**走不同航线/挂靠港**给出不同价时（MSC `via IPANAMA / via CARIOCA / via SANTANA`），把走法并进目的港字符串区分（`基本港 via CARIOCA`），不要合并成一条。
15. **引用回复（quotedMessage）必须解析**：`dws chat message list` 对引用回复会返回 `quotedMessage{content, createTime, openMessageId, sender}`，被引用的原消息全文（含图片 mediaId）一起带回来，**不需要回拉历史**。群里大量关键状态就藏在引用里：
    - 回复"无 / 售罄 / 没了 / 满了"引用某条现舱 → 把被引用那条对应的舱位记录标「已被覆盖」（能对上 openMessageId 就按它定位），引用本身不单独成行
    - 回复带调价（"还有200左右的空间""5个以上再减100""+500/CNTR"）引用旧报价 → 以被引用报价为基价生成新记录，备注写"基于 <原消息时间> <原发送人> 的报价，本轮另减/另加 X"；**没有绝对金额就海运费留空**，别自己算
    - 被引用消息常早于水位线（如 9/1 引用 8/25 的报价）→ 这是正常现象，按引用内容入库，不要因为原消息不在窗口内就丢弃
    - `消息原文` 由 `compose_text()` 自动附带被引用原文（本条全文 + `——引用 <时间> <发送人> mID=<被引用消息ID>——` + 被引用逐字全文），记录自带引用上下文；备注里**只补一句引用结论**（如"售罄""基于原报价另减X"+引用时间），不要把被引用全文再抄一遍进备注
    - 拉消息的 `--jq` 必须带上引用字段，否则等于丢信息：
      `--jq ".messages[] | {t:.createTime, s:.sender, id:.openMessageId, img:[.resourceRefs[]?|.resourceId], c:.content, q:{t:.quotedMessage.createTime, s:.quotedMessage.sender, id:.quotedMessage.openMessageId, c:.quotedMessage.content}}"`
      落盘 `msgs_*/<slug>.json` 时 `q` 一并存。
16. **目的港/起运港写法（台账匹配实测口径，2026-09-10 校准）**：台账匹配是"折叠后精确命中"（`fold()` 只去音标/大小写/`.` `,` `'` `-` `()`，无相似度），**同名多国必须消歧**。按可靠性排序：
   - **首选 LOCODE / 中文名 / 常见英文名**：`MXZLO`、`COCTG`、`TRMER`、`USORF`、`曼萨尼约`、`Norfolk` 都能命中；`ORF/PEL/BAL`（美东三字码）、`ISTANBUL`（→Ambarli）、`ALIAGA`（→Aliağa）已在主数据登记为别名，发原样即可。
   - **带国家后缀的写法只有"已登记成规范名"的才命中，不是通用格式**：实测 `ports` 里带括号的只有 7 行（`Caldera(CL)`/`Caldera(CR)`、`Cartagena(CO)`/`Cartagena(ES)`、`Port Elizabeth(US)`/`(ZA)` 等真跨国同名港），这些走 name_idx 精确命中、可依赖（闸门用例已钉成回归项）。但 **`Manzanillo(MX)` 命中不了**——库里只有一个 `Manzanillo`（country=MX，别名含 `MXZLO`），巴拿马那个 Manzanillo 根本没登记（而 `CAR`/`MEX` 港群成员串里却写着 `Manzanillo(PA)`/`Manzanillo(MX)`，属主数据不一致，待补）。**所以别给任意港名硬加 `(XX)`；消歧一律首选 LOCODE（`MXZLO`/`COCTG`）或中文名。**
   - **裸同名港判歧义 failed**：`Cartagena`（CO/ES 同名）、`卡塔赫纳`（中文也同名）→ 必须带 LOCODE。COSCO 加勒比表里的 Manzanillo 是巴拿马（`Manzanillo, PA`），PIL/MSK 墨西哥线的是墨西哥（`MXZLO`），**按航线上下文选对那个**。
   - **`中谷` 能命中**（是 `ZGWL` 别名），别当缺失；`CLSAI`→`San Antonio` 是**正确命中**（CLSAI 是圣安东尼奥智利的 LOCODE），不是误伤。真正要小心的是别把报价里的纯数字/产品代号当港口发。
   - **真缺的港**（如 `Aliağa`、美东三字码）走人工维护补进 `ports` 主数据（`/api/master/save`），不是 agent 自动写；agent 仍"识别到什么发什么"，命中不了交台账判 failed。
17. **有效期兜底窗（2026-09-10 定稿：运价、舱位都必填）**：`VALIDITY_REQUIRED_KINDS={rates,space}`，两库都强制有效期非空。报价常只给船期不给区间，统一走 `validity_parser.derive(text, msg_date)` 三级补，返回 `(有效期起, 有效期止, 船期ETD, ai_default)`：
   - **有明确区间**（`9.15-9.21`）→ 直接用 `有效期起/止`，**不标 AI判断**。
   - **无区间但有开船时间 ETD**（`9/16`、`9.12 ETD`、裸日期 `2026-09-16`）→ `有效期起=消息日`、`有效期止=开船日`（即"当前时间→开船时间"，"当前时间"取**消息日期**保证可重放），**不标 AI判断**。
   - **既无区间又无 ETD**（`case by case`、空、纯产品代码）→ `有效期起=消息日`、`有效期止=消息日+2天`，并置 `AI判断=是`。
   - **联动看板**：`ai_default=True` 的记录，运价/舱位看板在"有效期"处渲染"AI判断"标签（`ai_flag` 列），提示有效期是 AI 兜的、需人工核对。落地：`record_builder.rate/space` 与 `pipeline.step_build` 合并 LLM 记录时都调 `vdates`（=norm_v+derive），据 `ai_default` 写 `AI判断` 字段。
18. **船名里的公司 ≠ 船司（共船 / 舱位互换 VSA 是常态）**：能识别到 `船名航次`（如 `MSC OSCAR / 2637W`、`COSCO SHIPPING ...`）就把整串**照抄进 `船名航次`**，但**绝不能**从船名里那个公司名（MSC/COSCO/…）反推、回填 `船司` 字段——很多船司**共船、互相租舱（VSA）**，船东 ≠ 出这票舱位/报价的承运。`船司` 只能取自**报价来源**：群画像 `profile.carriers`、正文明示的承运人、发送人语境；三者都没有就 `船司` **留空**交台账判 failed，**别拿船名硬凑**。审/改时也别把"船司 ≠ 船名里的公司"当错误去"纠正"成船东。
19. **合并船司必须原样传串，禁止"取第一家"**（2026-09-11 事故：宁波群 `EMC/COSCO`、`HPL/ZIM/MSK` 被写成 `EMC`、`HPL`，伴生船司静默丢失，而且**校验照样通过**）。台账闸门已会按 `/ 、 ,` 拆分并逐个归一到 `carriers` 主键：全命中 → 自动展开成 N 条（每司一条，共舱语义）；任一 token 未命中 → 整条打回。所以 skill 侧**只管照抄原串**，不要自己挑一家、也不要预先拆。未知但形态像船司缩写的 token（2-6 位大写字母）台账会自动补一条 `carriers` 主键并在 `note` 里留"auto：待人工复核＋来源群/发送人/消息ID/原文"，人工可否决——**skill 不写主数据**。
20. **表头没有目的港列时，分段标题就是目的港**（2026-09-11 事故：宁波群空班/加班船表按 `南美西墨西哥 / 加勒比 / 南美东` 分段，判定层当成"没有目的港"，于是把 ETD 格里的说明文字硬塞进 `目的港`）。正确做法：`加勒比`→`CAR`、`南美东`→`ECSA`、`墨西哥`→`MEX`、`南美西`→`WCSA`（**按港群名存一条，不拆成员**）；`南美西墨西哥`这种合并段 → 同一行**存 WCSA、MEX 两条**。ETD 文字里出现"墨西哥加班船"这类区域词同样回填 `目的港`。
21. **多档柜型必须逐档配价**：`柜型="20GP/40HQ/HC/40NOR"` 时 `海运费USD` 要给 `"100/200/300"` 三个价，台账按位配对展开；只给一个价会被逐条打回（**闸门绝不把一个价复制给三档**）。另外别把 `40GP`（普柜）写成 `40HQ/HC`（高柜）——台账已取消那条悄悄归一，`40GP/45GP` 一律按"柜型只三档"打回。
22. **服务码 / 航线缩写 / 占位说明不是港口**：`ESE`、`BP`、`Base Port`、`Port group`、`NE Port`、`Argentina 1`、`(未注明，只去Manzanillo/Lazaro/ESE)` 这类一律**不得填进 `目的港`**。识别到就把 `目的港` 留空、把整串原文写进 `备注`；含括号或说明词的串台账会单独报"含说明文字或服务码，只可填港名/港群名"。
23. **占位符不是值**：`船名航次`、`目的港`、`船司` 拿不到就**留空**，不要写 `(未注明船名)`、`未注明`、`待定`、`无`（此前有 22 条占位符船名"通过校验"，放行就会往台账写假船名）。台账现在按未填处理并打回。
24. **一格多船期拆多条；被放弃的行不得静默丢**：`9.6和9.13 墨西哥加班船` → 两条记录，各自带 ETD。表里判断不入库的行（如整段"X号跳港NB"）必须在同批某条记录的 `备注` 里写明"本图另有 N 行跳港未拆"——2026-09-11 那张图 OCR 只留 14 行、实际 39 行，缺的 25 行**没有任何提示**，这属于丢数据。多维合并（船司×港口×柜型）展开超过 60 行时台账只落一条"超过上限"工单交人工，所以**能按原文配对就配对传，别指望闸门做笛卡尔积**。
25. **港群/航线归属的出口是"提候选"，不是自己改字典**：发现某群反复用一个缩写代表一片港（如 `NBE` 指巴西北部几港），**不要**直接往 `port_groups` 加成员——港群是放大器，一个成员加错会让整群价被错误展开。正确做法：`POST /api/pending` 带 `kind=group_suggestion`，字段 `港群 / 标签 / 类型(pol|pod) / 成员(逗号分隔，必须是 ports 规范名) / 来源群 / 消息ID / 消息原文`，人工在待审页「港群建议」签放行才真正写入；成员里有虚构港名会整条打回（报"成员港不在 ports 规范名里"）。同理，**航线是港口的子属性**（`ports.route`，台账已按港群成员种子化，航线空缺时按目的港派生）：采集侧发现某港航线缺失，也只提候选、不猜值。
