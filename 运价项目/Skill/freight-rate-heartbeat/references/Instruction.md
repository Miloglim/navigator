# references/ —— 按需查的文档 + 逐群规范

> 都是"细则/记录"，不放代码。别全文背进上下文，按当前消息类型/阶段查对应小节即可。脚本副本已从本目录移除（代码只在 `../scripts/` 存一份，避免漂移）。

| 文档 | 什么时候看 | 内容 |
|---|---|---|
| `群聊规范/<群名>/规范.md` | **处理某个群的消息前必读**（逐群差异） | 13 个群各一份：定位 / 报价格式 / **缩写表（带"列 + 群"作用域）** / 已知坑 / 解析要求。标「待补」的禁止猜测填充。检索规则与目录↔群slug 对照见 `群聊规范/README.md` |
| `extraction-rules.md` | 判一条消息能不能入库、怎么抽字段前 | 24 条微调口径：起运港三级判定、四档柜型、有效期解析、引用回复处理、原文逐字，以及 19-24（合并船司原样传串、段名即港群、多档柜型逐档配价、服务码/占位符不当值、被放弃的行要交代）。台账化改版后第 3 条(覆盖)等已按"只 insert 新行 + 台账判更新"重写 |
| `runbook.md` | 拉图/识图/提交/排障时 | 执行坑位表：dws 下图路径、按 mediaId 归位到 `images_dir`、水位拉取自愈、常见故障(连不上8795/401/一批全 failed=主数据缺) |
| `learnings.md` | **每轮开工先读**；被用户纠错时**当场追加** | 用户改进要求 / 纠错事项 / 已废弃做法 / 主数据缺口。带日期倒序，只追加不删旧条 |
| `data-review.md` | 搭完拉取 cron、准备再建"数据审查 agent"定时任务时读（**建前须征询用户许可**） | 台账数据审查 agent 规范：先摸清库结构 → 只读审查 `/api/audit`·`/api/pending`·`/api/master` → 按清单归因 → 给可执行修改建议（**不自动写库**，人工放行） |

## 台账口径的权威不在这里

字段名、枚举合法值、哪些字段必须命中主数据、价格整数、有效期 ISO、`消息时间` 对 agent 的处理——这些**唯一权威是台账的 `Database/docs/agent-input-contract.md`**（和它实现的 `/api/validate`）。本目录只讲"怎么从群里抽、怎么判定"，不定义"库要什么"。

- `pending-quality-review.md`：主动待审业务复核每轮必读。领取→原文/原图/对应群知识→有依据一次修正→结案→窄范围沉淀；独立于原只读体检及采集预检流程。
