## 柜型未明示时的参照补全（2026-09-30 用户重申）

## 报价格式与习惯写法（杜佳仪风格）
- 一行常是 `船司 + 起运港 + 航线 + 舱位状态 + 多个目的港 + 价格` 混排。
- 两个裸价 `2850/3700` = 两档柜型（`20GP` / `40HQ/HC`），逐档配价（extraction-rules.md#21）；只给一个价会被逐条打回。
- `+ENS` / `含OWS` / 亏舱费 / 超重费 等**附加费一律进 `备注`**，不加到裸价上（#10）。
- `POL:` 段给起运港集合、`POD…:` 段给目的港集合；多 POL **逐港拆条或存港群名**（#1），不能只取第一个。
- 表格里 `RATE` 列与 `VOLUME` 列并排时，只要该行有价格，就按 2026-10-22 新口径双入运价和舱位。

## 运价 / 舱位 判别（配合 extraction-rules.md#27 / #28）
- **任何价格先入运价 → `freight_rates`**：裸价、价卡、带价现舱和 `RATE + VOLUME` 行都先生成运价，价格写 `海运费USD`。
- **带价现舱双入**：同一行再生成一条同源舱位。运价只保留起运港、目的港、船司、柜型、海运费、ETD、船名航次、有效期和备注等兼容字段；`价格USD`、舱位类型、箱量、箱型箱量、库存、截关等只进舱位，金额不重复写。
- **无价格的现舱动态 → `space_records`**：只有没有可入账金额的现舱/配额/售罄/船期动态才进入舱位表。
- **舱价同源 → 逐行判断**：纯价格行进 `freight_rates`；无价舱位动态行进 `space_records`；同时有价格与舱位事实的行双入。

## 通用坑（这几个群都会犯）
- **币种混用**：`亏舱费600人民币` 是 CNY，而 `亏舱费` 列按 USD 口径 ⇒ 金额照抄进 `备注` 并写明币种，**不换算、不自算汇率**。
- **服务/航线代码不是目的港**（配合全局 #22）：`NE1/NE2/NE3/NE4`（北欧航线服务）、`BEX`(Bosphorus Express)、`FAL1/FAL2/FAL3/FAL5`、`CES`、`KCM2`、`MEX`、`SE1`、`DIR`+数字（直达天数）等都是**服务/航线码**，一律进 `备注`，**绝不拼进 `目的港`**。
  反例（本群踩过）：把 HPL 欧地特价写成 `目的港=欧洲基本港NE1` → failed。正确：`目的港=欧洲基本港`、`备注` 记"服务NE1/NE3/NE4"。
- 一行多目的港同价 ⇒ 按 `/` 与顿号拆条；`宁波- ISTANBUL` 中间的连字符不是分隔符。
- 这几个群脏值集中 ⇒ 解析保守；拿不准的核心字段（起运港/目的港/船司）**留空交台账判 failed，绝不编造主数据值**。
- 船名里的公司 ≠ 船司（#18）；合并船司原样传串不挑第一家（#19）。

## 土耳其港名消歧（2026-09-29）

- `Izmit`（伊兹密特，主数据规范名 `Izmit`，含 `IZMIT`、`IZMIT KORFEZI`、`Kocaeli` 等别名）与 `Izmir`/`İzmir`（伊兹密尔，主数据规范名 `Izmir`）是两个独立港口，不能互作别名、不能因拼写相近互换。
- `ALIAGA (IZMIR码头)` 表示 Aliaga 港的 Izmir 码头说明，不能改成 Izmit；`GEBZE/IZMIT` 只能按原图语义核对，不能改成 Izmir。
- 识别土耳其港名时必须同时核对原图英文、中文、LOCODE/主数据和该行上下文；其中任一证据冲突就保留原文并交人工，不用相似度猜港。
- 历史别名日志中曾出现 `Izmit → Ambarli` 的错误记录。该记录不再作为识别依据；Ambarli 是 Istanbul 的码头/港口语境，不能把 Izmit 归为 Ambarli，也不能把 Izmit 改成 Istanbul。
