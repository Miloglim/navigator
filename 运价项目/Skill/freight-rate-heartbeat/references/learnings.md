# 运价心跳 · 记忆文档

> 用途：存放**用户提出的改进要求**、**做错过要纠正的事项**、**已废弃别再碰的做法**。
> 用法：交互采集开工前读；定时采集在首次解析前读现行规则一次，无新增跳过，按公共提示词加载。用户提出新要求或指出做错时，立即在对应分区**追加一条带日期的记录**（倒序，最新在上）。别删旧条，只追加或标注"已过时"。

## 用户改进要求（最新在上）

- **2026-10-23｜解析阻塞不能把已明确产品整组藏掉。** 港口、价格、柜型和费用语义已能确认、仅有效期或次要条款缺失时，仍须生成待审行并让该单一校验错误可见；不得因 coverage 停止而返回零条。目的港或业务范围本身无法证明时，保留已有 awaiting/failed 行，只提出一个精确业务问题，不猜字段。

- **2026-10-23｜引用跟进明确延期时要形成可见版本。** 本条只写“沿用到10/31”等明确延期、并引用一套完整报价时，应从引用正文复用港口、价格和柜型，当前消息 ID 重建成新有效期待审；ISPS/ENS 等只留备注，不能只写一条不可执行的 review issue 后把延期丢掉。

- **2026-10-23｜海运费必须有独立币种，默认 USD。** 录入、待审编辑和 Agent 输出都在海运费旁携带 `币种`；未填写时按 USD，明确 EUR/CNY 等原币时保留原金额和币种，不再要求用户看原图或把金额留空。历史无币种记录兼容为 USD。

- **2026-10-23｜引用内容的图片只展示和校验哈希，不参与解析。** 大多数引用是相互提问/回复，少有真正内容更新。引用消息中的图片仍应下载可展示副本并计算 SHA-256，成功时写入 `图片名` 供看板显示；但不得进入 vision、抽取或独立盘点，也不能据引用图片复制产品。只解析本条消息自己的图片；引用正文仅作上下文。引用展示图下载失败不阻塞本条业务解析。

- **2026-10-22｜带价现舱稳定双入：运价 + 舱位。** 任何带价格条目先识别为运价；若同时有舱位事实，再额外生成一条同源舱位。金额只写运价的 `海运费USD`，不重复写舱位的 `价格USD`；港、船司、柜型、ETD等共同字段可按各自契约保留，`舱位类型`、`箱量/箱型箱量`、库存、截关等只进舱位。普通带价运价只入运价，无价现舱动态只入舱位。两条记录必须使用同一 `消息ID`。

- **2026-09-30｜柜型不确定不能直接留空，必须先查相似航线或相近港口。** 原文有价格但未明示柜型时，先参考同船司、同航线或相近港口、相近日期/有效期、相同起运范围和费用口径的已确认报价。有唯一稳定口径就填写柜型，在备注记录参照并标AI判断；只有可比参照互相冲突时才保留未知。不能把整条压成“保留原文待核对”，也不能因柜型一个字段不确定而丢掉明确的港口、价格、船期和船名。该规则已同步全部15份群规范；判定自查拦截“原文明示金额但运价缺柜型/价格”的占位输出。

- **2026-09-29｜定时提示词精简并按阶段加载。** 开工不全量读目录说明和历史知识；有本轮消息才读现行抽取/纠错规则，解析哪个群就完整读对应群规范、继承规范及业务沉淀，图片和初检修正再查对应契约。未变化文件复用，不跳过模板对应知识；压缩恢复后重核当前来源，不反复贴原文或重送历史。用户可见结果使用表格并区分预计/实际耗时。提示词与离线检查不证明实际解析准确率提升。
