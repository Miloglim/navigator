# 全局航管识别规则

规则版本：1.4.0；业务口径来源：用户 2026-09-28、2026-10-02 明确提出的身份过滤要求。适用所有运价采集群，一群可以有多名航管，身份按群＋DWS 账号独立判断。

## 识别依据

| 依据 | 如何计算 | 结论 |
|---|---|---|
| 本人发过 @所有人 | 只检查本条正文，不检查被引用内容；当前 DWS 仅返回正文标记，没有结构化群发属性；仅文字要求他人群发、Markdown 引用中的标记不视为本人群发 | 按用户规则识别为航管；界面注明正文代理证据 |
| 消息量明显较高 | 按消息 ID 去重，不按拆出的运价条目数计算；比较同群普通成员的消息数量 | 单独命中只列候选，不能认定其他人不是航管 |
| 工作日频率稳定 | 仅统计有完整采集证据的已结束周一至周五，缺采集日期为未知，不当作零条 | 与消息量差距同时成立，识别为航管 |

“航管身份”只表明消息发布人的业务角色；他的询价、催单、操作通知仍不自动成为报价。引用原航管消息的回复不能继承原发布者身份。原始正文与引用分别保留，审核/校验结论不因识别结果而更改。

## 初始计算参数

这些是实现初值，不是用户提供的固定阈值，也不代表统计准确率；集中定义在 `scripts/freight_identity/core/contracts.py`，后续根据真实反馈调整并更新规则版本。

- 观察窗口为最近 28 天；当天尚未结束，不参与全天稳定性统计。
- 至少 10 个完整工作日；活跃日比例至少 80%，日消息量变异系数不高于 0.8。工作日零条仅在全天采集完整时计为零。
- 消息量至少 10 条，且达到同群其余成员消息量下半部分中位数的 3 倍；至少有 2 个可比较成员。下半部分作参照允许多名航管同时具有高消息量，不只取第一名。
- 群内样本量差距及占比可用于候选提示；全天采集不完整时，它们只描述已观察样本，不能作为长期稳定性结论。
- 完整工作日依据：成功拉取回执＋当前原始响应哈希一致＋完整 JSON 信封（分页结束、无截断/解密失败、数量一致）。成功回包按内容哈希保留在运行目录 `raw_archive/`，回执用 `raw_file` 指向对应回包；内容相同不重复保存。连续采集时间段需覆盖整天两个零点才算完整，不完整边界日排除。旧扁平缓存、水位年龄、某天有消息都不能单独证明全天完整。
- 原始回包归档会占用本地磁盘；当前按哈希去重，尚未设置自动保留期，不自动删除历史证据。

- 周末不参与频率计算；目前没有法定节假日或人员请假日历，因此不额外推测缺勤。调休等例外后续应由明确日历输入处理。

## 身份与使用边界

新 DWS 压缩消息保留 `senderId`、`senderOpenDingTalkId`；引用中两字段另存于 `q`。优先以群＋OpenDingTalkId 归属，其次 senderId。同群同名的历史样本若仅对应一个可靠账号，合并入该账号的行为统计与看板行；无对应账号或出现多个不同账号时仍单列。原始消息身份字段不改写；无账号 ID 的消息即使并入统计，也不按账号排除。

当前正式页面从「账号管理 → 报价发布人」进入，与采集共用同一份账号名单和同一套识别函数。管理员可确认、明确排除、恢复规则识别；航管登录账号仅可查看。未知身份保留在原始证据和身份观察队列，但不进入报价解析；只有明确判定为航管的群＋账号才进入模板/LLM/OCR。仅姓名证据不允许确认或排除账号。人工排除优先于 @所有人等自动特征。恢复规则识别表示撤销人工决定，不代表强制改判非航管；已排除的历史消息不自动补投，可按归档另做受控重放。历史审核结论不变。

## 同步契约（5.7.0）

- 单一事实源：`scripts/config/publisher_roster.json`。1.3.0 的 `members` 保存按群确认的航管和“当前群＋完整姓名”的无 ID 排除，`exclusions` 保存稳定 ID 的全局排除人员；兼容1.0.0至1.2.0并按稳定 ID 合并旧群级排除。每次保存保留操作人、时间、原因、变更前后名单及修订号。
- 航管确认按群＋Open ID（优先）或发送人 ID 匹配；排除按人员稳定 ID 全局生效，覆盖现有和新增来源群。姓名、画像不能替代账号执行排除或合并；同名只用于唯一账号的行为统计，冲突证据保持观察。已管理账号无近期消息仍展示，消息计数不会伪造。
- 保存以文件锁、乐观修订校验和原子替换防止并发覆盖；名单缺失、损坏或版本无效会明确失败，采集不回退空名单。两端不得另建独立白名单。
- 采集在解析阶段读取名单，模板和 OCR 都应用明确排除；合并 LLM 输出时同样排除本轮被排除消息。提交前及每个提交批次前检查名单修订号，变化则重建并重做预检；已提交记录按内容签名保留，不重复投递。正在执行的 HTTP 请求不会追溯撤销，下一批次应用新名单。
- `run_*/identity_decisions_r<revision>_<timestamp>.json` 保存本轮每条消息的账号依据、动作、修订号与数量；`identity_review_queue.json` 单独保存观察项，观察模式下不会阻断报价解析。自动规则未命中不等于非航管。
- 未确认或明确排除的账号可在该轮完成持久化身份审计后参与水位结算；缺审计、路径越界或修订不一致则失败，不伪装 DONE。原始缓存及哈希归档保留，抑制只作用于后续解析，不修改历史待审条目。
- 页面按同群同名且唯一账号合并历史证据，保留来源群、账号、本人群发量、消息量比较、工作日覆盖/活跃、每日趋势、原文例子、账号变更以及采集应用修订；合并行标明历史样本条数。无完整采集日的条形使用斜纹且 tooltip 明示未知，不能算零条。
- 回归：`test_publisher_sync.py`（共享名单、并发、作用域、覆盖证明、模板/OCR 排除、提交变更与审计门控），`Database/test_publisher_accounts.py`（真实隔离 HTTP 和权限→共享采集判定）。没有新增依赖。
