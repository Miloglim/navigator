# 已知陷阱

- 中心账号模式下，Navigator 本地 `operators` 只承担业务身份和产品偏好镜像，不能继续作为昵称、头像或成长真源。本地会话查询不得要求 `password_hash` 非空。
- 中心模式改密必须调用 `/api/account/password`；不得继续执行本地 `UPDATE operators SET password_hash=...`。
- 2026-10-26：中心桌面登录返回 `mustChangePassword=true` 时，必须先建立只允许退出和改密的本地受限会话，不能继续查询会过滤首次改密账号的 `/api/navigator/access`。业务接口保持 `password_change_required`；改密成功并撤销旧会话后，用户重新登录才进入正常产品准入。
- 登录失败不得向匿名用户区分账号不存在与密码错误，统一“账号或密码错误”；只有密码已经验证的停用/归档账号、已认证无 Navigator 准入和中心服务不可用分别提示。不得把“无权限”当成首登改密的通用兜底。
- 2026-10-26：中心模式普通 GET 的 30 秒鉴权缓存只能使用明确白名单，写操作、导出、管理、监控、账号维护和未列明接口必须实时验证。缓存键同时绑定本地会话和中心访问令牌；登出、改密、撤权及令牌轮换必须清理，不能把读缓存误用到敏感操作。
- 首屏字体必须同源加载；不要再把 Google Fonts 样式表放进渲染关键路径。字体路由使用固定文件白名单、`font/woff2` 和 immutable 缓存，不接受任意路径。
- 当前正式 Navigator 页面本体经本机 SSH 隧道回源，整页 `no-store`。150 并发健康/状态接口通过，不代表 150 个整页冷加载通过；容量验收必须单独测整页。面向 150 人同时打开时，先把静态 HTML/JS/CSS/字体迁到云端，再保留小型 API 回源。
- 业务经验先写本地不可变事件和 `account_growth_sync_outbox`，再补传中心；不能只在页面读取时临时计算，也不能因中心暂时离线丢失事件。

- 2026-10-21：`manualdb.query_grouped` 的 SQLite 缓存探测必须在 PostgreSQL 适配器转换。漏掉 `PRAGMA database_list` 会先让事务进入 aborted 状态，表面错误却是后续 `/api/rates_grouped` 的“当前事务被终止”；不能只捕获或重试最终查询。

- 2026-10-21：运价服务启动器优先使用项目自有 `Database/.runtime/python`，不要再把 `psycopg` 只装在 Codex 共享 Python；共享运行时更新会使 8795 无法启动。采集任务注册只能在真实 `DESKTOP-6PSGIS4\YQN` 会话执行，`CodexSandboxOffline` 没有令牌、DWS 用户目录和计划任务权限，不能据此判断生产授权失效。

- 2026-10-18：权限测试必须区分角色可调用与参数有效；公司查价任务GET无id返回400，不能要求每个已授权GET无参都200。管理员已在authorize中继承OPS集合，不能再把OPS并入ADMIN独占集合，否则会让角色隔离测试把航管接口误判为管理员独占。前端测试缺DOM方法或共享函数时修测试上下文，不为模拟环境给生产代码加跳过保护。
- 2026-10-18：Windows PowerShell 5.1从pwsh继承PSModulePath时可能无法自动加载Set-Acl所属模块；令牌权限设置直接用.NET FileSecurity/File.SetAccessControl，不依赖模块自动加载。令牌内容不进入日志或对话；收紧权限不等于发现令牌已泄露，不无故轮换中断采集。

- Navigator 页面与知识库页面跨域，不能直接读取对方浏览器 `localStorage`；原浏览器未开放调试接口，也不能强行重启或接管其用户目录。知识库登录交接只能由本机管理员主动打开独立浏览器窗口，读取结果后即关闭调试窗口，续期凭据仍由 DPAPI 保存且不得回显。

- 公司船司匹配的input_key是输入回显，score=100也不能证明身份；只能对照code/name/match_text与已确认本地别名。港口去重音可能产生同名，须优先港口代码并核对国家，城市type=4不能作为具体港口type=11直接查价。测试公司的HTTP路由时必须替换真实凭据提供器，否则会意外读取本机DPAPI配置并访问生产网关。

- 多群/航线公告的兼容group_name为空不代表全体，必须先读取target_groups/target_routes，再回退旧单群字段。编辑缺省范围与显式空数组不可混淆，前者保留原范围，后者才清空；不能为多个目标复制公告或绕过销售置顶审核。

- 纯附加费通知不能生成空运价占位：例如图片原消息只有 CMA OWS 更新，随后回复明确写“超重费调整”。回复及其引用图片应共同归为非台账通知，把规则沉淀到群知识；只有同时存在完整基础报价时才生成运价，附加费仅进备注。

- 船司报价自编码不能覆盖官方 LOCODE：MSK 文本中的 `ECPOS` 指向 `Posorja`，但 UNECE 官方 LOCODE 是 `ECPSJ`。主数据保留 `locode_ref=ECPSJ`，将 `ECPOS` 作为 `Posorja` 的识别名；否则会把同一港拆成两个对象，或污染标准码字段。

- 等级重置保留流水时，数据库points>0约束不能塞负数；使用account_growth_reset正数抵扣标记，总经验统计时扣除，日额度排除该记录。有效经验按map_legacy_xp(v1)+v2净额计算，不能直接对原始SUM(points)清零。

- 旧lookup_port先读群级别名，可能把已登记规范名Ambarli改回ISTanbul、El Dekheila改为Alexandria。规范名必须先按统一识别器确认，别名不能劫持；折叠重名不能返回后来者。

- 同消息唯一的免箱期/亏舱费不等于全消息通用：船司、港口、服务或船期不同的段落不能互相补字段；继承必须限制为同产品的柜型行。

- 同批消息里的区间报价与单船报价可能有效期重叠，却不是同一个产品。暂存去重不能互相覆盖；同批不同有效期/ETD保留各行，同日期冲突价仍需覆盖审计。采集有未解决覆盖缺口时必须保留COVERAGE_PENDING，不能写DONE后宣称完成。

- 港群多个叫法不是多个对象。name存规范名，aliases承接旧规范名/简称，members只存港口规范名；合并重复对象必须比较成员、特例和方向，先停用旧行再承接别名。历史报价不强制重写，查询需兼容旧别名；nogroup=1只关闭成员展开，不能关闭别名归一。前端使用服务端portGroupIndex，禁止自己first-win匹配标签。

- 群规范表中的反引号不是别名映射契约：“各自规范港名（NB=Ningbo）”里的NB是举例，“不是港口，进备注”是业务处理说明。不能把唯一反引号值当所有写法的目标；这些表述必须保留为业务复核项，禁止自动迁入别名库。

- 欧洲价格群的 `GDK/FXT` 是港口缩写组合：`GDK=Gdansk`（格但斯克），`FXT=Felixstowe`；Gdansk 与 Gdynia 是两个不同港口，不能因缩写未登记而留空或互相替换。

- ONE 加勒比价卡的 `D2/D4/D5/R5 NOR` 是表头柜型，不是可忽略的图片文字：D2→20GP，D4/D5同价→40HQ/HC，R5 NOR→40NOR；黑底无价行不生成空报价。

- 名称统一必须与报价解释分离：`alias_scope`还存有ctype和space_type规则，不得迁入港口/船司/航线识别器。港群同名候选不能first-win；已登记规范名不能被其他实体的别名覆盖。群规范文件夹名不一定等于实际来源群名（例如加号与斜杠），迁移清单必须通过chat_sources.json的spec_dir定位来源群。
- 导入manual_server模块时CFG仍是默认SQLite，不能调用conn()假装检查正式PostgreSQL；只读审查工具须明确读取runtime.json、连接正式后端，并拒绝空主数据成功结论。只读接口数组返回使用`{ok:true,data:[...]}`，现有core.contracts.ok只接受Mapping，不要扩大公共helper而影响旧调用。


- 带明确FAK价表的消息同时写BASKET/T0成本调整，不等于整图无绝对报价。原文明确FAK且识图缓存有价格单元格时必须保留图上基准海运费，备注注明不是折后合约成本、不代算折扣或附加费；不再把是否写入price_basis=FAK作为唯一放行条件。纯公式或没有绝对价格继续留空。2026-10-08复核还发现MSC缓存多处价格误读，修复必须逐单元格核对原图，不能只把备注中的数字搬回价格。
- PostgreSQL 上线后，双击启动入口不能固定使用缺少 `psycopg` 的 YQN OS Python，也不能遗漏后端而默认打开旧 SQLite。两个入口探测已有驱动的 Python，调用 `ops/watchdog.py` 读取 `ops/runtime.json` 并核对健康端点的后端；启动输出追加日志，不能吞掉导入错误只展示旧日志。
- Windows 启动批处理保留 CRLF；UTF-8 中文入口先切换代码页。启动器输出写 `manual-startup.log`，不要重定向到守护子进程也要打开的 `manual.log`，否则 Windows 文件共享限制会让子进程启动报 PermissionError。
- 定时采集不能把新一天尚未生成的 `state.json` 当成丢失直接 ABORT。先调用 `pipeline.py start --date <MMDD> --shard <A或B>`，用返回的 `data.state_file` 定位；无本轮产物才初始化，已有状态不覆盖，存在本轮产物却缺状态才停止。禁止从历史文件拼 `new_ids`；状态写入须原子替换。
- DWS `resourceRefs` 同时包含图片 `mediaId` 和 PDF 等文件的 `fileId`，不能把所有 `resourceId` 都塞进识图队列；按 `resourceIdType/type=mediaId` 识别，且真实图片 ID 可以以 `@` 或 `$` 开头，不按前缀猜类型。2026-10-07 补采曾把两份 PDF 误当图片，下载报 `RESOURCE_NOT_FOUND`。
- 历史 `pending_records.check_status=passed` 只是当时的机械校验结论，不证明报价/舱位明细完整。2026-10-07 复核发现 7 条现舱占位虽通过但未拆目的港、航次或箱量，其中一条还把亏舱费当售价；放行必须按当前规则重校验，不能信旧徽标。新增的现舱明细闸门只保护加载新代码的服务，未验证重启前不得称线上已生效。
- 多价表达 `5500/5800/40NOR 4400` 中，`5800/40NOR` 不是独立的金额/柜型配对；价格配对正则不能从更长的斜杠链中间起匹配。应结合原文、同群已确认柜型顺序分别识别两档基础价和明示 NOR 价，不把格式闸门的通过当成业务确认。
- 群消息用 Markdown `~~...~~` 划掉的旧报价保留在消息原文供审计，但不能作为当前有效价格覆盖检查的必提项。2026-09-17 美加 ZIM 消息把 LA/CHI 旧价划掉；校验器曾误要求提取，修复后仍须逐项核实未划掉的价舱范围。
- 带图消息不能因为同条文字已有模板或 LLM 判定，就在缺 `ocr_cache/<mediaId>.json` 时进入提交。旧 BUILD 只在缓存存在时核图片维度、缺缓存直接跳过，存在只提交文字半成品的窗口；缺任一图缓存必须按消息隔离并保留水位。

- 舱位判定不能用只有“保留原文待核对”的空记录把聊天回复送入待审；`现舱` 至少要有目的港、船名航次或箱量等可定位事实。`亏舱USD100/柜` 是费用，不是 `价格USD=100`；机械校验通过也不代表源图行数、港点和价格已完整核对。

- 定时采集的 `LLM_PENDING` 是可恢复处理中间态，不是 `ABORT`。入口必须优先恢复当天未完成的 run；任务收尾必须读取 state，非 `DONE` 就让调度器报失败并保留现场，不能接受 Agent 单方面把未完成工作报告成结束。

- 定时采集提示词的群规范配置键是 `spec_dir/spec_base`，队列输出才是 `spec_path/spec_base_path/spec_knowledge_path`。知识回执只证明文件可读，不能证明Agent理解；歧义要查全局与当前群知识并核对来源及适用范围。入口统一引用公共正文，避免独立旧副本覆盖异常处理要求。

- 运价记录的复合起运港必须先按 `/`、`+`、逗号等分隔符拆成独立港口再做主数据校验；正则中的空白符必须是 `\s`，误写成 `\\s` 会把 `QINGDAO+TAICANG` 当成不存在的单一港名并阻塞整组提交。

- 模板命中不能只看标题或正则成功：稳定模板要登记港口名称集合、港口数量、生成条目数量和产品唯一性指纹。固定版式零容差，可变版式最多显式允许2至3项变化；任何模板外含价行都必须整条转Agent，不能用容差接受部分解析。

- DWS未引用的消息也可能带字段全为null的`q`对象；模板不能用`bool(msg.q)`判断引用，必须检查引用正文是否非空。否则普通报价会被误判为引用消息并落回LLM。

- “长荣西岸指导卖价”不能交给通用语义模型自由合并：标题已确定船司EMC，WSA2后的两个航次必须结构化分开；WCSA/MX拆WCSA和MEX，GTZNJ是Puerto Quetzal而不是Puerto San José。ETA CNXHK只进备注，不冒充ETD。柜型按本群同模板历史稳定价序补全并标AI判断。模板入口同时核对完整结构签名，不能只匹配标题中文字。

- “柜型未明示”不等于“整条无法识别”：必须先查同船司、相似航线或相近港口、相近日期和费用口径的已确认报价。有唯一稳定口径就填柜型、备注参照并标AI判断；只有参照冲突才保留未知。曾有HPL土耳其报价把宁波、Istanbul/Izmit、3700、船期和船名全部压进“保留原文待核对”，后续又被错误批量同步目的港。判定自查必须拦截原文明示金额却缺柜型/价格的运价占位记录。

- 规范港名与别的港口别名撞名时，前端不能整键丢弃：Colón规范名曾被Cristóbal的Colon别名遮蔽，导致联想可选但保存回退，服务端却能通过。前端唯一规范名优先于普通别名，与后端name_idx一致；两个规范名自身折叠撞名仍拦截，不能靠数组顺序消歧。不要为修UI把不同码头合并。

- select 切换 appearance:base-select 后，旧的 height/padding/font 行高不能假定仍由原生控件垂直居中。必须显式 align-items:center 与可容纳中英文的行高，同时对齐 picker-icon；验证34px筛选、36px表单、账号偏好及28px编辑工具栏，不能只验展开菜单。

- 同类控件不能在各页重新定义：销售与航管页面标签复用同一组规则；主按钮、次按钮及公告提交复用公共按钮定义。尺寸、圆角、主色、焦点及弹层遮罩从 index.html 的公共变量取值，新增局部样式必须保留只读、校验失败和已填状态，不能用统一背景覆盖业务状态。顶栏导航、工具分段切换、普通标签分别承担不同层级，不强行混成一种。

- 公告作者/角色只能来自服务器会话，不能信任请求正文；富文本保存前必须白名单净化，禁止原样HTML持久化。销售编辑已置顶公告必须重新审核，否则可以审批后替换内容绕过审核。
- 发布及图片读取是异步操作，退出/切换账号后旧回调不可恢复草稿或改新账号编辑器状态；使用账号代次校验。公告业务迁移的id是文本，不能按自增表调用setval；旧快照/归档缺公告表须向后兼容。

- 航管“我的条目”是按账号绑定的稳定 publisher_id 匹配的展示条件，不是航线/群权限。不能用可编辑显示名称归属条目，不能匹配不到就回退全量；销售/管理员不设置责任航线。列表、计数、批量操作必须使用相同ownership选项。旧账号范围列仅兼容快照，不再执行。
- PostgreSQL的JSON兼容不能只支持消息ID；按发送人查询、从resolved派生航线也必须通过相同适配器，并做真实PG隔离回归。

- 只缩短公共提示词不够：SKILL/learnings若仍要求定时开头全量读取，会让按需加载失效。读取时机在入口与纠错文档同时对齐；不删适用业务规则，群规范完整读取，机械知识回执不代替模型阅读。切群不会自动清空上下文，压缩后必须从本轮状态和原证据恢复，不能靠摘要造字段或重送；字符减少不是准确率提升证据。

- 别名管理分页必须在SQL筛选后LIMIT/OFFSET，不能全量下载后前端切片；搜索或翻页并发时旧响应不得覆盖新页。别名管理列表的懒加载不改变报价归一所需的主数据加载。

- A/B 定时提示词各存完整正文会漏同步，应用内任务的旧内联指令也可能覆盖新报告格式。四个应用内采集任务与 Windows 分片入口统一引用 `ops/codex-heartbeat/prompt-common.md`；修改流程只改公共正文，分片仅由入口固定。同步必须核对两类入口，不得顺手启用已暂停任务；配置检查不代表真实采集已验证。
