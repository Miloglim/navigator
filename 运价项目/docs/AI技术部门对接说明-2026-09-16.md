## 2. 功能链路与数据流转

```
钉钉群(11) ─dws 按水位线增量拉取(每群1次,逐字落盘 .work/msg<MMDD>/<slug>.json,含引用原文)
   → record_builder 模板直出候选(中文字段)          ← 命中模板 0 LLM
   → 未命中/低置信/新图 → LLM 判定(llm_out_<D>/*.json) + 识图(ocr_cache 跨群复用,原图落 Database/images/)
   → POST /api/validate(只读预检) → POST /api/pending(唯一写入口)
        台账侧 expand_cn：船司多值拆 N 条 / 柜型逐档配价 / 别名归一(先群作用域后全局) / 航线按 pod 派生 / 脏值打回
   → pending_records(待审核, check_status passed/failed)
   → 人工在 web「待审核」点放行 → 再过一遍闸门 → 判新增 or 更新留痕(supersedes) → freight_rates / space_records
   → web 看板：折叠视图现算"当前生效"；港群双向展开；详情带逐字原文+原图
```

纪律：**进待审 ≠ 入库**；**只 insert 不改写**；**归一唯一真源 = 台账 Master**（skill 禁自拼映射）；agent 不写主数据（港群/船司只提候选）。

接口面（读免口令，写需令牌）：
`GET /api/rates /api/space /api/rates_grouped /api/space_grouped /api/master /api/options /api/audit /api/export`
`POST /api/validate /api/pending`（agent 唯一写入口，kind=rates|space|group_suggestion）
`POST /api/push /api/record/* /api/master/save /api/operator/save /api/pending/approve|reject|delete`（人工口子）

## 4. 每运行一次的效率边界（实测）

| 环节 | 边界 | 实测 |
|---|---|---|
| 拉取 | 每群 1 次 dws 调用，**水位线后增量**；0911 全量回填 237 条/11 群 | 单群最多 65 条 |
| 模板直出 | 命中模板 0 LLM | 0911 批直出 99 条（运价 58+舱位 41），**直出率 30%**（该批含大量图与自由文本；纯文字模板群更高） |
| LLM 判定 | 仅三类：模板未命中、conf=med 复核、新图识图 | 0911：228 条判定 + 76 张首次识图；稳态增量下 ≈ 新增非模板消息数 |
| 识图缓存 | `ocr_cache/<mediaId>.json`，同图跨群不重识 | 76 张缓存 |
| 机械校验/写入 | `/api/validate` 1000 条 ≈ **0.086s**；`/api/pending` 1000 条 ≈ **0.14s** | 2026-09-10 实测 |
| 提交上限 | 单请求 ≤1000 条；单条消息展开 ≤**60** 条（超过只落一条"超限"工单） | MAX_EXPAND=60 |
| 分页 | 待审 API 单页 ≤500；前端每页 50 | PD_PAGE=50 |
| 幂等/去重 | `content_key` 指纹；同产品身份待审**撤旧留新**；放行时再判新增/更新留痕 | — |
| 规模参照 | 48h 回填：237 消息 → 2132 待审（6 子 agent 并行） | 单轮稳态远小于此 |

**成本构成**：token 主要花在 LLM 判定与识图；机械侧可忽略（<1s/千条）。降成本杠杆＝提高模板命中率（`record_builder.py` 加模板）与识图缓存复用。

**当前采集是停的**：QwenWork 定时任务 3 个全部 `enabled=false`，且 prompt 里写的还是旧目录（`Documents/运价项目/heartbeat/run.py`），最后运行 2026-09-08。恢复需启用并改指向 `运价项目/Skill/...`。

## 5. 数据库构成（11 表，SQLite）

| 表 | 行 | 关键字段 |
|---|---|---|
| `ports` | 1190 | `name` 规范名主键；`aliases` 识别名；`locode_ref`；`kind`(pol/pod/both)；`route` 航线子属性（已填 41） |
| `carriers` | 50 | `code` 主键；`aliases`；未知船司由闸门自动补并标 `auto：待人工复核` |
| `routes` | 30 | 子线；`region`=6 族（美加/欧地/拉美/澳新/亚洲/非洲线） |
| `port_groups` | 9 | 群名/标签/成员；成员保存强制命中 `ports.name` |
| `alias_scope` | 36 | `(alias, kind, scope_group)` → `target`；群作用域别名（`NB`→宁波 等）；**其中 9 条(space_type/ctype)无消费点，已定挪走** |
| `senders` | 15 | 主键嵌电话 8 条（待拆列） |
| `freight_rates` | 279 | 见字段映射；`content_key` UNIQUE；`supersedes` 留痕 |
| `space_records` | 208 | 同上骨架 |
| `pending_records` | 2300 | 待处理 1813 / 已放行 487；`payload` 中文 JSON + `resolved` 归一缓存 |
| `chat_groups` | 11 | `cid` + `default_pol` |
| `operators` | 0 | 分区可见性未配人 |

中→英落库映射（节选）：起运港`pol` 目的港`pod` 航线`route` 船司`carrier` 柜型`container_type` 海运费USD`freight_usd` 价格USD`price_usd` 有效期起止`valid_from/valid_to` 有效期船期`validity_raw`(原文) 船名航次`vessel_voyage` 舱位类型`space_type`(11 档) 消息原文`message_text` 消息时间`message_time` 消息ID`mid` 图片名`image_file` 来源群`source_group` 发送人`sender` AI判断`ai_flag`。
**对接陷阱**：读出来英文列名、写进去中文字段名；金额是字符串；status 两表字面量不同（`当前生效`/`当前有效`）。

## 7. 接手方必读的坑

- 宿主裸 `python` 是 WindowsApps 桩（exit 49 无输出），必须用绝对路径内嵌解释器。
- `sqlite3.Row` 没有 `.get()`（本项目已踩过两次）。
- dws 是宿主 shim：子进程调不到；bash 里禁管道/重定向/`&&`/cd 前缀；长 JSON 用 `--records-file`。
- 同一时间只让一个会话改 `manualdb.py` / `web/index.html`（9-14/15 那轮扩 `alias_scope` 未记变更汇总，状态行仍写"未动代码"）。
- 改 `manualdb.py` 后必须重启服务；前端改动跑 `js_check`+`web_check`。
- 已定口径待执行：挪走 9 条死种子、收束变更汇总、北巴另立子线（NEB 8 港 route=北巴）、operators 配人（缺名单）。
