## 1. 这套系统是什么

把 **11 个钉钉报价群**里的海运运价、舱位动态，自动整理成一张可查询的台账：

```
群里的报价（文字/表格图） → 自动识别整理 → 航管在"待审核"确认 → 销售可查
```

两条底线：**没经过人工确认的报价不会出现在查询结果里**；**改价不覆盖旧记录**，旧价留痕可查历史。

## 3. 怎么打开、谁能看

- 本机：浏览器开 `http://127.0.0.1:8795`
- 同事电脑：`http://<这台机器的内网IP>:8795`（需先在这台机器跑一次 `allow-lan.ps1` 放行）
- **查询免口令**；录入、放行、改主数据需要口令，只发给航管。
- 目前**没有按人过滤**，所有人看到全部数据；配好"谁负责哪几条线/哪几个群"之后，各人只看到自己负责的部分。

## 4. 关键名词（业务口径）

| 名词 | 意思 |
|---|---|
| 当前生效 / 当前有效 | 这条报价/舱位现在能用；同一条线改价后，旧的那条自动变"已被覆盖" |
| 已被覆盖 | 被更新的报价顶掉了，还在库里，展开历史能看见 |
| 有效期 | 报价适用的起止日期；群里没写日期时系统按船期兜底，并打上 **AI判断** 标签提醒人工核对 |
| AI判断 | 有效期是系统按规则补的，不是群里原话，需要人工确认 |
| 目免（Freetime） | 目的港免用箱天数 |
| 亏舱费 | 订舱后不装货要赔的钱 |
| T/T 航程 | 海上运输天数 |
| 港群 | 一片港共用一个名字，如 `MEX`=曼萨尼约+拉萨罗、`NEB`=巴西东北/北部 8 港；查其中任何一个港，群价都会一起出来 |
| 航线族 | 6 大线（美加/欧地/拉美/澳新/亚洲/非洲），下面共 30 条子线，如 欧地线 下有 欧基港/北欧/地东/黑海… |
| 来源群 / 消息原文 / 原图 | 这条数据从哪个群来、群里原话、原图——对不上时点详情核对 |

## 5. 为什么有时候查不到（五个常见原因）

1. **还没放行**：报价在"待审核"里，航管没点放行。
2. **信息不全被打回**：群里没写船司、目的港或船名，系统不允许猜，标成"未过"等人工补。
3. **过期了**：有效期止已过，折叠进历史，不在"当前"里。
4. **港口写法没登记**：新港口或新缩写（如某群自创缩写）没进主数据，需要先补。
5. **采集任务当前是停的**：见下一节。

## 6. 数据多久更新一次

- **设计频率**：工作日 9:00–13:00 每小时一轮、14:00–18:00 每 10 分钟一轮，自动拉群。
- **现状：三个定时任务全部停用**，且任务里写的还是旧目录。所以现在的数据更新靠**手动触发**（人工跑一轮采集）。
- 要恢复自动采集：把任务重新启用并把目录改到新位置，一句话的事，等你点头我就改。

## 7. 发现数据错了怎么办

| 情况 | 走哪 |
|---|---|
| 某条报价数字/日期错 | 看板「待审核」里改字段后放行，或驳回重报 |
| 新港口 / 新缩写 / 新船司 | 航管在「主数据」里补；或让采集 agent 提"候选"，航管确认后生效 |
| 某个群的说法系统总认错 | 在该群的《群规范》里补一条缩写对照（11 个群各有一份），下次自动生效 |
| 联系人 | 航管数据负责人：＿＿＿；系统问题：＿＿＿（待填） |

## 9. 给对接程序 / 对方 agent 的一页纸

- **读数据（免口令）**：`GET /api/rates`、`/api/space`（逐条）、`/api/rates_grouped`、`/api/space_grouped`（折叠+历史）、`/api/master`（港口/船司/航线/港群字典）。
- **三个最容易踩的坑**：
  1. 读出来是**英文列名**（`pol`/`freight_usd`），写进去用**中文字段名**（`起运港`/`海运费USD`），别混。
  2. 金额读出来是**字符串**（`"8444"`），要自己转数字。
  3. 状态字面量两表不同：运价表叫 `当前生效`，舱位表叫 `当前有效`。
- 完整字段表与示例 JSON：`docs/agent-input-contract.md`。
