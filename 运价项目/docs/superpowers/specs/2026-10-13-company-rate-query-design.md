# 公司系统运价查询接入设计

## 目标

在销售查询中并行展示已审核的钉钉群运价、可选的公司内询运价和可选的船公司实时价格；公司系统查询、保存或失败不得阻塞本地运价查询。

## 范围

- 钉钉群运价继续使用现有 `/api/rates` 与 `/api/rates_grouped` 查询，始终执行。
- 公司内询运价由用户勾选后触发。
- 船公司实时价格由用户勾选后，通过显式操作启动“创建任务 -> 轮询结果”。
- 本期不接入船期、舱位和起运港附加费。
- 公司结果保存，但不写入 `freight_items`，不进入待审核或正式放行链路。

## 架构与数据流

销售请求到达后，本地查询立即执行；外部查询作为独立任务执行。外部任务拥有独立超时、并发和错误状态，结果通过任务状态/结果接口补充到页面。外部写入在结果返回后异步完成，写入失败不改变已返回结果。

多港查询按已确认的具体港口 ID 形成起运港 × 目的港组合，最多 20 组，受控并发。城市必须先展开为具体港口；不得把城市聚合 ID 直接用于船司实时价格。每组组合独立成功或失败。

公司网关只从后端环境读取 `YQN_DINGTALK_TOKEN` 和 `YQN_USER_ID`。令牌只放外层 `Authorization`，业务用户 ID 放转发体 `body.header.xUserId`。两者均不得返回前端、写入普通日志或进入台账记录。

## 保存与复用

外部结果长期保存为独立历史记录，至少包含：来源、完整查询条件、港口/船司 ID、柜型、日期/重量、原始响应摘要、规范化结果、请求时间、状态和错误信息。

历史记录另有“可复用有效期”判断。有效结果可立即展示并后台刷新；过期结果仍可追溯，但不得标记为当前价格。建议初始有效期为：公司内询 15 分钟，船公司实时价格 5 分钟；该值应配置化，不能写成散落魔数。

## 接口契约

新增接口统一返回 `{ok, data?, error?, code?}`：

- `POST /api/company-rates/query`：接收本地规范化查询条件和港口组合，创建公司内询任务，立即返回本地结果引用与任务 ID。
- `GET /api/company-rates/tasks/{id}`：读取任务状态、分组合结果和错误，不触碰本地运价查询。
- `POST /api/company-rates/realtime`：创建船公司实时价格任务；只接受用户显式提交的船司、柜型、日期和重量。
- `GET /api/company-rates/realtime/{id}`：读取实时任务状态和按船司结果。

公司网关目标接口仅由服务层调用，不直接暴露给浏览器。船公司实时查询必须使用本次创建返回的 `taskId`，首轮空结果表示未完成，不表示无报价；轮询预算耗尽时记录为未完成。

账号偏好在现有 `preferences_json` 中新增 `company_rates_enabled` 与 `carrier_realtime_enabled` 两个布尔字段。偏好只控制是否发起查询，不扩大权限；保存后按账号跨设备生效。

## 错误与性能边界

- 本地查询不等待公司任务、缓存命中、网络请求或历史写入。
- 公司接口 401、令牌过期、超时、限流、解析失败和单组合失败均转换为该来源可见状态；本地结果仍成功返回。
- 并发组合数最多 20 组，并设置服务端并发上限、单任务超时和总预算。
- 不在主查询事务中执行外部 HTTP 请求。
- 结果按来源分区展示，不能把公司缓存或实时价格伪装成钉钉群报价。

## 验证标准

- 本地查询在公司接口延迟、失败和保存失败时仍按原契约返回。
- 两个偏好可保存、读取和跨会话恢复。
- 多港组合最多 20 组，组合之间状态隔离。
- 有效历史结果可复用，过期历史结果不会标记为当前价格。
- 实时任务只使用本次返回的任务 ID，并能区分完成、失败、未完成和空结果。
- 所有新增接口均返回统一 envelope，并覆盖鉴权、参数校验和错误分支。
