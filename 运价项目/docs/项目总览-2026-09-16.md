## 1. 架构：三个部件，一个连接点

```
① 采集器（skill：freight-rate-heartbeat）
   钉钉群 ─dws 按水位线拉消息（逐字落盘，含引用原文）
     → record_builder 模板直出候选（模板没命中的才交 LLM，省 token）
     → 图片首次识图写 ocr_cache/<mediaId>.json，原图落 Database/images/
        │
        └── 唯一出口：POST /api/pending（中文字段 JSON；不碰库文件、不碰人工口子）
② 台账（Database/：manualdb 数据层 + manual_server 接口层，SQLite 单文件、只依赖标准库）
   闸门：归一 → 拆多值 → 逐档配价 → 派生航线 → 挡脏值
     → pending_records 待审 → 人工点"放行" → 业务表（判新增 or 更新留痕）
③ 看板（web/index.html，8795）
   销售端：查询/折叠现算当前价/CSV；航管端：录入/批量导入/待审核复核/主数据维护
```

三条纪律：**进待审 ≠ 入库**；**只 insert 不改写**（改价追加新行、旧行标已被覆盖，当前价由看板折叠现算）；**归一只有一个真源**（台账 Master，skill 不许自拼第二套映射）。

## 2. 落库用的标准化字段

采集侧传**中文字段**，闸门归一后写**英文列**：

| 传入（中文） | 落库列 | 标准化动作 |
|---|---|---|
| 起运港 / 目的港 | `pol` / `pod` | 折叠匹配 `ports` 规范名或港群名；**先查该群专属别名（`alias_scope`）再查全局别名**；多港按 `/`、顿号拆条；命中不了 → failed |
| 船司 | `carrier` | 联盟/共舱串（`ONE/HPL/MSC/HMM`）逐个归一，**全命中才拆成 N 条**；未知但像缩写的自动补 `carriers` 主键并标 `auto：待人工复核＋出处` |
| 航线 | `route` | 30 条子线；**为空时按目的港的 `ports.route` 派生**（只补空、不覆盖明示值）；族（6 个"××线"）从 `routes.region` 现取，不存 |
| 柜型 | `container_type` | 只三档 `20GP` / `40HQ/HC` / `40NOR`；多档必须**逐档配价**；`40GP` 不再被悄悄归成高柜 |
| 海运费USD / 价格USD | `freight_usd` / `price_usd` | 非负整数；加价公式不自算，拿不到绝对金额就留空 |
| 有效期起 / 止 | `valid_from` / `valid_to` | ISO 日期；缺区间按兜底窗补（有 ETD→消息日至开船日；都没有→消息日+2 天并标 `AI判断`） |
| 有效期船期 / 船期截关 | `validity_raw` / `cutoff_raw` | **原文照抄**，只供核对，不参与计算 |
| 船名航次 / 舱位类型 / 箱型箱量 / 箱量 | `vessel_voyage` / `space_type` / `box_desc` / `box_qty` | 舱位类型十一档（含空班/跳港/首航）；占位符 `(未注明船名)` 按未填处理 |
| 消息原文 | `message_text` | 逐字、含引用块；参与判重，不许截断改写 |
| 消息时间 / 消息ID | `message_time` / `mid` | agent 必须传真实群时间（折叠排序与留痕靠它） |
| 来源群 / 发送人 | `source_group` / `sender` | 放行时自动登记进 `chat_groups` / `senders`，只补缺不覆盖 |
| 图片名 / 运价图片·舱位图 | `image_file` / `image_url` | 存引用不存字节，看板按 mediaId 前缀回原图 |
| 备注 / 记录状态 / AI判断 | `remark` / `status` / `ai_flag` | 附加费、服务码、运河路径等说明全进备注 |

字段按性质分四类，防护不同：**核心值**（强校验，命中不了就挡）、**时间**（可排序判过期）、**溯源原文**（宽松，只给人看）、**系统列**（指纹/留痕，不参与内容指纹）。

**结论先行：没有职责重叠的表，没有外键冲突**（有意不加硬外键，避免阻断录入）；DDL 与代码列由 `_migrate()` 幂等对齐，无漂移。但有 **7 处冗余/空转**，按"能不能删"分级：

| 3 | `ports.city` / `city_pinyin` | 各 **40/1190** 非空，且已退出匹配键源 | **可删**（展示价值低，中文查询走 `name_cn`） |

| 7 | `operators` 整表 | **0 行**，但 scope 过滤逻辑贯穿四处查询 | **已定：配人**（机制已就绪：`/api/operator/save`+前端管理页） |

**明确不是冗余的三处**（别误删）：

- `validity_raw` vs `valid_from/valid_to`：原文 vs 解析结果，一个给人核对一个给机器算，性质不同。
- `pending_records.resolved` vs `payload`：归一结果缓存（2300/2300 非空），卡片显示"归一 X/Y/Z"靠它，放行时会重算。
- `routes.region` vs `ports.route`：一个是"族的归属"（30 子线→6 族），一个是"港口的子属性"（41 港），层级不同不冲突。

**一处结构问题（非冗余）**：`senders` 主键里嵌了电话（**8 条**，如 `孙丽洁 Emma -0574-87236750`）——换号就会变成两个发送人、频次统计与权限归属断裂。待拆 `name`/`phone` 两列（涉及主键，需迁移窗口）。
