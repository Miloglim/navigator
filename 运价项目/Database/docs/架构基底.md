# 架构基底

## 2026-10-21 运价提取常驻引擎（0.6.0）

运价提取生产形态从“外部时钟触发 + 临时唤醒 Worker”收敛为单个本机常驻服务。`services/schedule.py` 只负责 Asia/Shanghai 工作日窗口、A/B 5 分钟错峰、幂等时间槽和下一槽位投影；`transport/engine.py` 在服务内运行调度线程、2 个 Worker 执行线程和 HTTP 工作台。服务每个 tick 重新读取 `ops/freight-orchestrator/config/schedule.json`，可直接热更新调度规则；已持久化触发与任务不因配置变更被删除。服务不使用 Windows 计划任务、`schtasks` 或 Codex 自动化时钟。

执行仍由 `transport/store.py` 的 SQLite 持久队列、租约、代次和依赖约束驱动；Worker 只领取可执行阶段，Agent 阶段启动独立 Codex 子进程，DWS 拉取/原图下载和台账预检/送审/读回继续走 `transport/production.py`。同一群串行、不同群有序推进、全局并发上限、业务失败不自动重试、基础设施有限恢复及“只进待审核”边界不变。`start-service`、`stop-service`、`service-status` 提供脱离终端的启动、优雅停止和只读状态，`worker.lock` 拒绝同一控制库多实例。

`worker-health.json` 是服务和调度的实时运行快照，包含进程、启动时间、调度成功时间、下一 A/B 槽位、Worker 线程存活、任务状态计数和 DWS 状态；`dws-health.json` 只记录 `available`、`authorization_required`、`command_failed` 或 `invalid_response` 等固定状态，不保存 CLI 原始诊断和凭据。`/api/health` 与 Trace Studio 读取同一运行快照。2026-10-21 已完成隔离服务启停与 SSE 工作台验证，但生产服务尚未在 DWS 重新授权前启动。

## 2026-10-21 中心共享账号资料与成长

中心 `identity.users.display_name`、`identity.user_profiles`、`identity.account_experience_events` 和 `identity.account_growth_projection` 是跨产品共享账号资料与成长真源。Navigator `operators` 继续保存业务身份、角色、发布人关联与历史外键，并镜像显示名供本地列表检索；航线、群聊、默认页签、公司查价和船司查价开关继续写 `preferences_json`，不与共享资料混为一层。

中心模式密码只写中心 `identity.credentials`。Navigator 普通 API 会话通过 `/api/account/password` 改密，成功后中心撤销全部会话；本地 `operators.password_hash` 不参与，也不得被单独更新。

Navigator `/api/account/profile` 在中心模式合并中心资料与本地产品偏好。保存时中心资料先成功，再保存产品偏好；中心不可用时不得只写本地并声称账号资料已保存。中心模式会话验证不依赖本地密码摘要，`password_hash` 仅用于历史兼容或显式本地模式。

经验事实由 Navigator 业务服务写入本地不可变事件及 `account_growth_sync_outbox`，再由中心按产品、事件类型、主题键、规则版本和每日上限幂等记账。中心不可用时 outbox 保持 pending，登录、账号页和新经验产生时重试。中心投影是 UI 真源；本地经验表保留完整业务审计和离线补传来源，不能反向覆盖中心投影。

详细迁移、验证和回退见 `central-account-profile-delivery-20261021.md`。

## 2026-10-21 阿里云 HTTPS 反向代理与 Linux 备份（6.49.0）

Navigator 正式容器由 host 网络运行，只监听 `127.0.0.1:8795`；Caddy 终止公网 TLS 并把 `X-Forwarded-Proto: https` 转发到本机。仅当显式设置 `NAVIGATOR_TRUSTED_PROXY_HTTPS=1` 且实际 peer 为私有/回环地址时，服务才把该请求视为安全代理请求；其他来源的转发头不能提升 Cookie 或 Origin 判定。代理调用中心使用本机 `http://127.0.0.1:55847`。

PostgreSQL 启动备份不再硬编码 Windows `pg_dump.exe`。非 Windows 默认使用 `/usr/bin/pg_dump` 与 `/usr/bin/pg_restore`，也可由 `PG_BIN` 覆盖。Navigator 容器镜像预装 `postgresql-client` 与 `psycopg` 运行依赖，避免每次重启访问 apt/pip。阿里云 Compose、Caddyfile、环境模板和 Dockerfile 由 Prospector `deployment-templates/aliyun/` 维护。

## 2026-10-21 中心账号唯一真源与产品业务映射

中心 `milogin_center` 是账号、密码和产品准入的唯一真源。Navigator 的 `operators` 在中心鉴权模式下只保存业务身份、角色及历史关系，不作为独立账号密码库；正式超级管理员 `admin@yqn.com` 已映射到原本地管理员业务编号，保留原历史和角色并撤销旧本地会话。中心 `/api/navigator/access` 专用只读准入查询同时接受有效 API 与浏览器会话，统一返回身份和 Navigator 角色；8795 不再额外调用 `/api/auth/me`。Prospector 开发启动器默认连接正式中心 `55847`，隔离测试中心 `55844` 仅用于自动化测试环境。

### PostgreSQL 折叠查询兼容

`manualdb.query_grouped` 使用 SQLite `PRAGMA database_list`/`data_version` 隔离折叠缓存。PostgreSQL 适配器必须兼容应答这两个探测；未转换的 `PRAGMA database_list` 会先触发 SQL 错误并中止事务，之后正式查询统一报“当前事务被终止”。`postgresdb.execute` 现返回数据库命名空间且不再污染事务，`PRAGMA data_version`仍返回每次变化的版本以禁用跨写入缓存。

## 2026-10-21 项目自有 Python 与采集恢复入口

运价服务不再依赖 Codex 共享 Python 中临时安装的 `psycopg`。项目运行时位于 `Database/.runtime/python`，由最小 Python 3.12 标准运行时与项目声明的 `psycopg` 依赖组成，已被 `Database/.gitignore` 排除，不进入源码提交；`Database/.venv` 只作为兼容备用。`Database/运价看板-启动并打开.bat` 按项目运行时、`.venv`、Codex Python、YQN OS runtime 的顺序探测，只有能导入 `psycopg` 的运行时才允许启动 PostgreSQL 后端。已运行中的共享 Python 实例可由 `Database/重启运价库-项目运行时.bat` 在真实 YQN 桌面会话切换为项目运行时。

采集恢复入口为 `ops/task-scheduler/restore-freight-tasks.ps1`，按当前 `run-orchestrator.ps1` 生产入口生成上午 A/B、下午 A/B、拉取健康检查和中断恢复六个交互式 Windows 任务。脚本默认只预览，`-Apply` 必须在真实 `DESKTOP-6PSGIS4\YQN` 桌面会话执行，并主动拒绝 `CodexSandboxOffline`。`run-orchestrator.ps1` 使用项目运行时、动态发现当前 Codex CLI，并在触发时唤醒 8796 监控；旧 `run-heartbeat.ps1` 不再作为生产调度入口。

## 2026-10-18 Agent 令牌文件保护

`ops/token_security.py` 是启动阶段文件权限适配器，由 `manual_server.ensure_token` 在读取或写入令牌前调用。Windows 使用系统 PowerShell 的 .NET ACL API，只允许当前服务身份、SYSTEM、Administrators；其他平台设为0600。权限设置失败拒绝启动，不记录凭据。沿用现有 `token_manual.txt` 路径和有效令牌值，采集端不必变更；不代表本机管理员或拥有项目目录控制权的主体被隔离。正式启动仍使用 `运价看板-启动并打开.bat` 的 PostgreSQL 驱动探测，不能任意改用无驱动的 Python。

## 当前架构与迁移边界

当前版本采用渐进拆分，而非在销售试点期间重写台账。新代码遵循 `core/ -> services/ -> transport/`：

- `core/`：零依赖的 HTTP 契约、状态值和非敏感配置解析。
- `services/`：零 IO 的发布策略与部署就绪判断，可用单元测试验证。
- `transport/`：HTTP 路由适配，只转发到服务与数据适配器。
- `services/monitoring.py`：将心跳回执事实汇总为群级健康度；不读取文件或数据库。
- `transport/monitoring_routes.py`：只读扫描 `heartbeat-data/.work/run_*/pull_receipt_*.json`，不读取原始群消息。
- `manualdb.py`：当前 SQLite 数据适配器与既有归一化逻辑；后续 PostgreSQL 迁移以它为替换边界。
- `ops/postgres_migrate.py`：PostgreSQL 建表、配置迁移与内容摘要校验工具；默认不迁会话或业务历史，且拒绝覆盖非空目标库。
- `ops/postgres_sync.py`：预切换阶段的自动配置镜像；只读取本机受限连接配置，同步后校验内容摘要。目标库出现报价、待审等业务数据即拒绝覆盖，不能替代正式数据适配器。
- `ops/backup.py`：SQLite 热备、恢复演练和可选异机副本工具；备份状态写入本地运维状态文件，不进入业务台账。
- `ops/load_test.py`：销售端鉴权查询的只读容量测试工具；凭据通过本机 `--credential-file` 读取，不打印；高并发必须显式确认，绝不调用写接口。
- `manual_server.py`：遗留路由与鉴权宿主。新端点不得继续向其中堆叠业务规则，既有 `act_*` 将按风险和变更频率逐步迁到 `services/`。

## 个人账号详情（4.4.0）

`operators` 使用稳定 `user_id` 作为账号身份，`name` 作为可修改登录账号，`publisher_name` 作为不随登录账号变化的报价身份；`display_name`、`preferences_json` 继续保存本人昵称与偏好。启动时增量补列并把旧账号的报价身份回填为原登录名。`services/account_forms.py` 无 IO 校验昵称及偏好，`ops/account_selfservice.py` 在会话账号下持久化，`transport/account_routes.py` 只转发资料读写；销售、航管和管理员均可进入“我的账号”，人员账号库仍只管理员可访问。

偏好含多选航线、来源群和默认运价/舱位页面。4.5.0起账号默认柜型偏好停用，旧ctypes字段兼容回传空数组，不迁移或改动销售查询中的手动柜型筛选。`services/account_forms.account_route_sections` 按主数据region和实际可见名称派生分区，遵循固定区域展示顺序，其他区域随后、未分区最后；不新增或存储分类状态。个人页支持分区全选/取消、逐条选择、搜索及区域计数。可选航线/群来自主数据，并在受限账号下按实际可见正式条目派生；退休或权限变化后的已选项提示重新选择，不静默回退全部。前端首次进入账号时加载并应用默认范围，不用浏览器共享存储。`default_routes`/`default_groups` 是 JSON 名称数组，分别在未提供显式 `route`/`group` 时缩小销售查询，所有条件仍与服务器账号权限相交。可临时取消个人默认范围，无法越过账号权限。

资料只返回本人昵称、登录名、稳定编号、角色、创建/密码修改时间及本人当前连接 IP/本次会话时间；IP 取 TCP 对端，不信任客户端转发头。`127.0.0.1` 代表本机访问，代理场景显示直接连接地址。个人资料修改不改变角色、业务授权、密码、会话或原始审计归属；SQLite 和 PostgreSQL 启动升级/全库备份包含新字段，无新依赖。

## 数据层

账号鉴权由 `core/contracts.py` 定义角色与身份契约，`services/access_policy.py` 无 IO 地计算视图权限和安全资料变更，`transport/access_rules.py` 显式列举各角色/采集器的 HTTP 能力，未知路由拒绝。浏览器账户角色优先于同时附带的采集令牌，不能凭令牌提升销售权限。

`operators` 继续作为统一账号表，唯一 `user_id` 支持 admin/operator/sales。历史身份按原登录名生成稳定编号，新账号生成独立 UUID；删除后重建同名账号不是原身份。管理员可修改 `name`，事务内保留 `user_id` 与 `publisher_name`、清理重置申请并撤销旧名会话；公告按 `user_id` 归属，历史署名保留发布时快照。`manualdb.ensure_account_schema()` 仅在初始化/启动执行兼容升级，旧快照恢复保留已存在身份；密码只保存 PBKDF2 摘要，会话表只保存 Cookie 摘要。4.5.1起新登录的会话和Cookie有效期固定为30天，从登录时起算，不随访问续期；已签发的旧会话保留原到期时间，重新登录才获得30天。密码没有按时间自动过期机制，密码/角色/登录账号变更或停用账号仍立即撤销会话。未新增留言/备注表。

PostgreSQL 的 `ensure_identity_schema()` 和账号升级均在启动前备份后执行；`postgresdb.Connection` 普通连接不执行建表/补列，避免每次校验身份和查价都获取结构锁。账号停用、密码/角色变更与会话撤销在同一事务内，最后一个可登录管理员受保护。普通资料修改不撤销会话，同账号多浏览器会话相互独立。

全部业务 API 和图片要求身份，销售只读销售业务，航管可审核及业务编辑，管理员可维护主数据/账号/运行配置。采集器单独读取受限令牌文件，常规报价写链路为 `POST /api/validate` 与 `POST /api/pending`；独立受控补档/待审修复接口依据各自证据契约开放，仍不能直接写正式报价或放行。首次管理员初始化后 `/api/local-token` 关闭。`GET /api/health/live` 公开但仅含存活状态/后端标记，不含任何业务数据。

`manualdb.py` 保留业务逻辑与 SQLite 适配；`postgresdb.py` 提供 PostgreSQL DB-API 兼容适配器。正式后端由 `ops/runtime.json` 的非敏感 `backend` 键供守护任务选择；`manual_server.py --backend postgres` 显式启动，连接密钥仅从本机受限 env 文件读取。业务记录采用一张 `freight_items` 表，包含价格、有效期、船名、箱量、舱位类型、目免和亏舱费等字段并集。

旧的 `freight_rates` 与 `space_records` 为只读兼容视图。所有写入、更新和版本链都经过 `freight_items`，不允许向兼容视图写入。

## 服务层

`services/port_routes.py` 是无 IO 的航线归属策略：规范数组/旧分隔字符串并计算唯一共同归属。`manualdb.py` 负责 `port_routes(port_name, route_name)` 关系表 IO；联合主键去重，外键约束归属目标存在。`ports.route` 仅保留旧接口兼容镜像，不作为多值查询事实源。

数据库初始化/服务启动仅在关系表不存在时迁入已有 `ports.route`，未知名称中止并回滚，不按地理或未审核群聊证据猜归属。清空后重启不得重新补回。港口删除清理关系；仍被引用的航线禁止停用/删除。新快照包含关系表，旧快照按已有字符串恢复；恢复在单事务内进行，不可替代 PostgreSQL 全库恢复演练。

新增前端字段为查询时派生/关系读取，不重写历史报价或待审结论。报价明示航线原样归一；未填时所有港群成员都有归属且共同交集恰好一项才派生，否则留空并给非阻断提示。编辑后刷新该提示，保留其他提示。销售航线查询仍精确匹配报价航线，不按港口归属扩散。

`js_check.py` 使用 Python 标准库提取页面脚本并交给现有 Node 的 `--check`，不替换现代语法、不新增解析依赖。Node 可来自 PATH 或 Codex 已安装的运行时；未找到时明确失败。

历史上 `manual_server.py` 仍包含部分 `act_*` 业务编排，不能宣称已完全分层。新的 `services/readiness.py` 与 `services/release_policy.py` 已作为迁移样板：它们不读取数据库、不读取环境、不发网络请求，输入事实后只产生可测试结论。

待审记录的 `errors` 只存阻止放行的硬校验错误；`warnings` 存需要人工查看但不阻止放行的提示，例如原文港口覆盖率。

审核页按来源消息归组呈现；组内每条候选独立展示和操作。来源消息 ID 只用于溯源与视觉归属，不用于合并柜型、船期或舱位字段。

Windows 任务 `run-heartbeat.ps1` 在正常结束（包括非零退出）时写入同名 `.result.json`，记录时间和退出码；进程被中断而未执行收尾时不会产生该标记。独立的 `monitor-pull-health.ps1` 在运行超过宽限时间后扫描缺失标记的日志，并在最近 45 分钟报告中断次数与轮次，即使之后的成功重试覆盖了 `LastTaskResult`。`RUN_TRACE_START` 限定上线时间，旧日志不被误判。该标记不供 Agent 解析使用。
`运价心跳中断恢复` 由 `ops/pull-health/recover-interrupted.ps1` 每五分钟作为 YQN/Interactive 独立运行：仅当 A/B 定时任务已停止、最近结果为 `0xC000013A`、故障发生在 2–30 分钟内才 `Start-ScheduledTask`；每片一小时最多两次，状态与动作日志仅保存在 `ops/pull-health/state/`。原 `monitor-pull-health.ps1` 保持只读并检查该恢复任务本身的健康。隔离测试中 Windows XML `RestartOnFailure=PT1M` 对此状态码没有自行补跑，故正式 A/B 任务未依赖该设置。

## 局域网账号保护与连接复用（4.2.0，2026-09-29）

`core/contracts.py`定义认证限额和受账号范围约束的GET列表；`services/access_policy.py`纯函数计算群/航线any/all及浏览器同源判定。`ops/account_security.py`承担内存限流、并发密码计算准入和数据库范围检查；HTTP只按服务端会话绑定viewer、操作人与写入范围。待审分页先筛范围，再聚合消息，不改审核结论。体检/健康/提示/队列同步筛范围；按航线授权而无法证明归属的群默认提示不展示。
