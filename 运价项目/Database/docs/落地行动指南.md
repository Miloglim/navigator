# 运价库落地行动指南

## 目标和边界

第一阶段服务公司局域网约 300 名销售：销售只查询已发布运价，航管审核待审报价，管理员维护主数据和运行状态。采集链路必须为全自动：钉钉 DWS 拉取 -> 原始证据留存 -> AI 解析 -> `POST /api/validate` -> `POST /api/pending`。禁止 Excel、CSV 或人工中转写库。

本项目当前已切换为本机单节点 PostgreSQL，适合受控试点，不应把“能跑”误判成“可承载公司级高可用”。前端和采集器只能通过既有 API 写入，尤其自动采集只可写 `/api/validate` 后的 `/api/pending`，不得调用 `/api/push`、`/api/record/*`、`/api/master/save`。

基础账号鉴权已实现：管理员全权限、航管销售/审核及业务编辑、销售只读查询；所有业务与图片需登录。管理员在主数据的库管理中维护账号，新建必须设密码，修改资料不使账号退出，改角色/密码或停用撤销会话。留言/备注暂不实现，钉钉 SSO 与 HTTPS 仍属后续接入工作。

## 落地链路

```text
钉钉群消息 / 图片
  -> DWS 拉取（群白名单、增量水位、幂等消息 ID）
  -> 原文和图片证据归档（来源群、发送人、时间、消息 ID）
  -> OCR / AI 结构化提取（字段置信度、推断痕迹）
  -> API 机械校验 POST /api/validate
  -> 待审台账 POST /api/pending
  -> 风险分流：可审核 / 缺主数据 / 解析失败 / 重复或变更
  -> 航管审核、留痕放行
  -> freight_items 已发布版本
  -> 销售查询 API 和主页面健康度卡片
  -> 审计、备份、复盘并回写规则候选
```

任何一步失败都必须留下可恢复状态和错误原因。水位只能在待审写入成功后推进；DWS 不可用、OCR 不可用或台账不可用时，应结束为可恢复的 `ABORT`，不能写成“无新数据”。

## 分阶段行动

### 阶段 A：试点前一周

1. 确定一名业务负责人、一名航管审核负责人、一名 IT/数据平台接口人；业务负责人拥有自动发布规则的最终签字权。
2. 在专用 Windows Server 或公司虚拟机部署，不使用个人日常办公电脑。固定内网地址或内部域名，开放仅必要的 8795 端口，并设防火墙白名单。
3. 使用独立服务账号运行服务和 DWS 任务；服务账号仅有应用目录和备份目录权限，不能是本机管理员。
4. 建立每天一次离机或网络盘备份。配置非敏感环境变量 `FREIGHT_BACKUP_TARGET` 指向已存在的网络备份目录，计划任务执行 `python Database\\ops\\backup.py --json`。该工具会先热备、做 SQLite 完整性检查、恢复到临时库核对行数，再复制异机并记录 `ops/backup-status.json`；未配置异机路径不等于灾备完成。
5. 把 10 至 20 个高质量群加入白名单，定义群负责人、允许来源发送人、默认航线和失效处理方式。先跑一周影子采集，只进待审不影响销售查询。
6. 用管理员账号查看 `/api/system/readiness`。SQLite、未配置异机备份、未接钉钉 SSO 都会显示为 `attention`，不能把它们忽略为绿色通过。

### 阶段 B：受控试点，两至四周

1. 按航线或销售小组逐步开放查询，不一次放开 300 人。
2. 每日检查待审量、通过率、失败原因、审核时长、重复率和群健康度的 12 小时、1 天、2 天、7 天趋势。
3. 所有价格均由航管审核发布。即使机械校验通过，来源变化、AI 推断、主数据新增、有效期短、明显变价都必须人工判断。
4. 每周把重复出现的失败原因转成主数据、别名或规则候选；修正规则后须重新体检和修复存量待审行，不能只修改下一条。
5. 每周做一次恢复演练和一次权限审查：离职、转岗和密码变更后对应会话必须失效。

### 阶段 C：正式推广条件

以下条件连续两周满足后，才扩大到 300 人并启动公司平台接入：查询高峰无明显锁等待；备份可恢复；待审写入可追溯；审核 SLA 稳定；群健康度可解释；来源和主数据变更有责任人。

容量测试只在低峰进行，且只打鉴权后的查询接口：`python Database\\ops\\load_test.py --credential-file Database\\token_manual.txt --clients 300 --requests 3000 --confirm-high-load --out Database\\ops\\reports\\load-test.json`。工具从本机文件读取凭据，不打印且不写库；令牌查询压测不包含用户登录开销，不能冒充完整销售会话压测。验收关注各接口 `p95_ms`、失败数和整体请求速率；任何非 200、超时或明显锁等待都阻止扩大销售范围。

向公司 IT/数据平台提交：接口清单、字段字典、数据保留期限、访问角色、审计要求、部署拓扑、备份恢复结果和容量数据。由平台团队提供 PostgreSQL、反向代理 HTTPS、钉钉 SSO 应用和服务账号后，再切换基础设施。

## 自动发布的保守规则

当前配置必须保持 `FREIGHT_RELEASE_MODE=review`，即使机械校验通过也进入审核。项目中的发布策略只输出解释性决策，尚未执行自动写库。

未来最多先做“受控自动发布”：来源群和发送人已白名单化、无 AI 推断字段、无主数据变更、有效期不少于 24 小时、相对上版变价不超过 15%、对应群机械通过率不少于 98%，并且存在可回滚的上一已发布版本。任何一个条件不满足即交航管审核。阈值应通过至少四周真实数据回放和业务负责人签字后启用。

## 自建到公司 PostgreSQL 的迁移

初期可以自建数据库，但建议直接在专用 VM 上运行，而不是个人电脑。当前 SQLite 用于试点的优势是零新依赖、备份简单；限制是单机、没有高可用、权限和连接治理有限。

迁移按以下顺序进行：冻结短暂写入窗口 -> 备份 SQLite -> 校验 `freight_items`、主数据、`pending_records`、审计和会话的数量与内容指纹 -> 导入 PostgreSQL 暂存库 -> 验证 API 查询和审核回归 -> 切换连接配置 -> 保留 SQLite 只读备份 -> 观察 48 小时。不得由前端或 DWS 直接连接 PostgreSQL。

接 PostgreSQL Python 驱动会引入新依赖，按工程约定须在实施前确认驱动版本、公司制品源、连接池策略和密钥管理。连接串、钉钉应用密钥和令牌不应发送到 Agent 对话中，应由管理员手动写入受控环境变量或公司密钥平台。

## 钉钉与公司平台接入清单

- 钉钉：企业内部应用、OAuth/免登回调地址、可访问人员/部门范围、应用管理员、退出或转岗同步策略。
- DWS：群读取授权、消息和图片字段契约、增量水位、失败重试、限流、审计日志与告警联系人。
- 反向代理：内部域名、HTTPS 证书、只允许公司网段、请求体大小与超时、访问日志脱敏。
- 会话：反向代理不得把用户会话绑定到源 IP；本服务的 Cookie 会话可跨 DHCP、VPN 和代理地址变化，账号变更或退出时仍立即失效。
- PostgreSQL：专用数据库与最小权限账号、每日备份、保留周期、恢复演练、监控与连接上限。
- 运营：航线主数据负责人、群负责人、审核 SLA、异常报价升级路径、销售反馈入口。
