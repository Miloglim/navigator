# 视觉设计与组件规范

状态：已采纳的设计基线，2026-09-30。适用于 `Database/web` 的销售、航管、管理员与登录页面；独立原型不属于生产实现。用户提出统一视觉规范，本文是组件语义与验收依据；代码实现程度逐项记录，不能把规范等同于全站已完成。当前生产样式变量以 `web/index.html :root` 为实现入口；组件布局可在独立 CSS 中维护，但不能重定义同名全局变量。

## 运价币种选择（6.52.0）

运价录入、待审编辑和“添加条目”中的海运费金额旁使用固定币种下拉，默认 `USD`，常用选项为 USD/EUR/CNY/HKD/GBP/JPY；现有记录缺少币种时编辑表单也显示 USD。金额仍是非负整数输入，币种独立存储，不把货币符号塞进金额。销售和待审价格文本显示为“币种 空格 金额”，例如 `EUR 1250`；非 USD 不再默认要求查看原图。

## 一眼识别

视觉语言是**深海军蓝导航、冷灰底、浅色卡片、清晰的数据层级**。页面结构先突出「我在哪、当前筛选、结果与状态、下一步操作」。颜色传达固定含义，不因页面或角色重新解释。账户头像和旧成长卡片曾存在局部绿色硬编码，并非有意的品牌或成长色；当前账号等级已收拢到头像下方。角色身份需要独立配色区分，保留超级管理员橙、管理员紫、航管蓝、销售绿，并始终显示文字。其他历史用色仍需按下方清单分批治理。

| 语义 | 现行变量/基准 | 允许场景 | 不用于 |
| --- | --- | --- | --- |
| 品牌、主要操作与选中 | `--primary #0f2b46`，浅底 `--navy-soft #eff6ff`；悬停 `--primary-hover #1a3d5c` | 顶栏、主按钮、活跃标签、账号首字头像与等级文字 | 审核成功、数据健康的真假判断 |
| 文本与画布 | `--ink #0f2b46`、`--ink-secondary #475569`、`--ink-muted #94a3b8`；`--bg #eceff3`、`--surface #fbfcfd`、`--panel-soft #f3f7fb`、`--border #dce4ee` | 标题、正文、辅助文字、表面、分隔 | 用低对比辅助灰展示关键数字或错误 |
| 经验进度 | 按循环递进的等级色 | 第 1 循环为纯蓝；第 2–7 循环为扁平渐变；第 8 循环及以上为带金边的金色渐变 | 审核、健康或账号角色判断；轨道与数值文字仍清楚可读 |
| 角色身份 | `--role-superadmin #b45309` 橙、`--role-admin #6d28d9` 紫、`--role-operator #1d4ed8` 蓝、`--role-sales #047857` 绿 | 个人页身份标签、账号库人员角色及对应经验条 | 不代替“可登录”“审核通过”等状态；只凭颜色不判身份 |
| 成功/通过/健康 | `--green #059669`、`--green-soft #ecfdf5` | 有证据的成功反馈、通过状态、健康阈值达到 | 头像、等级、低价、普通被选中 |
| 关注/待处理 | `--amber #d97706`、`--amber-soft #fffbeb` | 需要留意但尚非失败的状态 | 所有未选项或普通提示 |
| 风险/失败/破坏性操作 | `--coral #e8614d`、`--coral-soft #fef2f0` | 失败、风险、删除或退出悬停 | 常规关闭、普通筛选 |
| 旧版青绿交互强调 | `--accent #0d9488`、`--accent-soft #f0fdfa`、`--focus-ring #99f6e4` | **迁移中**：历史筛选选中、输入焦点等 | 新组件不要继续引用；统一到海军蓝交互与可见焦点 |

颜色之外必须有文字/数值/图例：例如“健康 98%”“关注 12条”“风险 3条”，不要让用户只凭红黄绿辨认。浅色背景不替代高对比的正文色。后台展示“未来生效”是时间状态，使用更浅的中性/品牌色并保留日期说明，不当作通过/失败。低价只是数值比较，不天然等于成功。

## 排版与空间

- 全局 `--font-body` 保证中文可读；品牌短标题可用 `--font-display`，ID、金额等对齐数字可用 `--font-mono`。正文 14px/1.6；表格与控件至少 13px；辅助信息 12–13px；11px 仅限次级元信息且不承载操作或审核结论。标题按 22px 页面、16–18px 区块、13–14px 表头建立层级。数字等宽优先，不把金额和单位拆成难读的两行。
- 间距以 4px 为基本步进：控件内 8/12px，相关字段 8/12px，卡片内 20/24px，区块间 20/24px。常规控件最小高度 34px，登录主操作整行可为 42px。现有 `--radius-sm 6px`、`--radius 8px`、`--radius-lg 8px`、三档阴影保持收敛，不另造随机圆角和大阴影。
- 桌面内容最大宽度 1400px，横向安全边距 24px；窄屏至少 16px。卡片应与页面边界留白，首要信息按“标题—筛选—结果—详情”排列。表格列能自适应则不滚动；长 ID/港口与多字段内容进入“详情”，不靠隐藏关键字段挤进一屏。

## 组件用例与状态

下表列的是生产页已有组件的推荐用法，不把示例类名当成新的公共 API。新增组件先复用现有类，确需新状态再加最小语义修饰类。

| 组件 | 正确用例 | 必须检查的状态 |
| --- | --- | --- |
| 主操作 `btn-apply`、`btn-submit`、`notice-submit` | 页面当前任务的一个主要动作，如“查询”“保存” | 默认、悬停、键盘焦点、处理中、禁用；禁用不能仅降低文字对比 |
| 次操作 `btn-ghost`、`btn-reset` | 重置、返回、取消 | 同高同圆角；危险操作明确红色悬停与确认文案 |
| 导航 `ops-tabs`、`cat-tabs` 与 `sub-tabs` | 页面级导航用文字和底线；工具内部模式用分段控件 | 当前项文字/底线与 `aria-selected` 或等价语义一致；无内容的“全部展开”不显示 |
| 输入 `filter-group`、`form-field`、`profile-field`、`auth-field` | 常规筛选、账号资料与登录 | 标签可见；清空、只读、错误、自动保存反馈；键盘焦点边界清晰 |
| 多选/单选 | 柜型固定选项用可多选高亮块；航线按地域分区；来源群精确匹配 | 选中兼有描边/文字，不只有颜色；空选、不可用、结果同步；不显示无意义勾形 |
| 结果表与详情按钮 | 运价/舱位表保持必要摘要，详情按钮按需展开来源、箱量等 | 桌面与窄屏；空/加载/错误；组不跨分页；排序标题说明方向；消息时间到分钟 |
| 状态 `badge-ok`、关注/风险变体 | 已审核、失败、群健康分别用明示文字和语义色 | 语义来自数据，不拿展示归属或颜色改写审核结论 |
| 看板图/进度 | 运行中心健康统计标注样本、时间窗、阈值与图例 | 数据为空/采集滞后/失败；灰底表示轨道，填充长度按实际值；tooltip 不代替基本说明 |
| 账号菜单/弹层/Toast | `account-menu`、`auth-card`、`modal-box`、`toast` | 宽窄屏、不裁切、Esc/焦点、成功与失败文案；字段错误在字段附近 |
| 头像/等级 | 未选择时首字头像用品牌浅底和深色字；头像悬停显示“更换头像”，点击头像打开选择器；30 张新版预设按女/男、人物、造型选择，旧头像已选项保留；头像下方胶囊显示“等级、圆角菱形、循环编号”，内部元素统一尺寸、字重和白色。第 1 循环使用纯色且不显示周期元素，第 2–7 循环使用无立体边框的扁平渐变，第 8 循环及以上使用无外部投影、仅靠边框与内高光形成层次的金色渐变；下接同色 XP 进度条 | 名称长、图片缺失、保存失败、移动端弹窗、等级读取失败；等级不是“健康” |

### 可复制的页面状态用例

**销售查询**：主查询放航线和柜型多选，查询按钮为主操作；高级区放来源群精确匹配、舱位类型及日期。空结果写“当前条件下无条目”并给“清除筛选”。入库时间和有效期各有明确列名。详情按钮 `aria-expanded` 与展开内容同步，键盘可操作。默认航线来自账号偏好，当前筛选仍可随时修改。

柜型适配：界面与报价表固定展示四档 `20GP / 40HQ/HC / 40NOR / 45HQ/HC`；公司接口或入口返回 `40GP` / `40DC` / `40DV` 时归入 `40HQ/HC` 价格档，不显示第五列。原始来源值只在详情/溯源中保留，不改变统一价格列口径。

**报价表（6.40.3）**：同一页面上方 OCEAN FREIGHT、下方 SPACE AVAILABILITY，每表底部合并单元格 REMARK；默认字段及顺序见 `QUOTE_COLUMN_DEFAULTS`。船司、POL、POD 使用库内主数据联想键入，候选与失焦归一只认船司规范代码及港口规范英文名，不匹配简称、中文名、别名或港群；自由键入的非匹配内容仍可保留。FT、TT 自动补齐 DAYS，手动编辑后及邮件复制时保持单位。其余单元格与列标题直接编辑，悬停列头显示拖动、添加、隐藏和删除；浮动工具栏不占用字段名布局。隐藏列以眼睛按钮恢复。单条竖表每行的“添加行”与隐藏/恢复按钮相邻，点击后在该行下方插入字段；新增字段删除工具也在同一悬浮组内，工具组浮动在字段名左外侧，不占表格列宽，触屏设备常显。单条竖表字段在 REMARK 上方展示并随邮件复制；横表末尾删除操作列固定窄宽。格式、内容和备注按账号在当前浏览器记忆，恢复默认格式保留已改报价内容。邮件复制使用紧凑内联表格，仅输出可见内容；标题、列顺序、相对列宽、相邻单元格合并、表头/价格/备注配色与当前界面一致，不复制拖拽、删除等编辑控件。开启自动合并后，页面和复制表体均取消交替深浅色行，避免合并单元格跨越不同底色。默认导入字段使用英文，已知中文航线转标准英文缩写；无法可靠翻译的中文值显示 —，供用户核实后编辑，不猜测英文业务事实。报价草稿不修改源运价，跨设备不同步。

舱位表每行只对应一种柜型的海运费，默认顺序为 `CARRIER, POL, POD, TYPE, O/F, ETD, ETA, VESSEL No., ROUTE, TT`。单条竖表同样将 TYPE 紧放在 O/F 上方；邮件复制沿用该顺序。来源未明确柜型时 TYPE 留空待核，不把“柜型”占位文字当成已确认值。旧默认布局的草稿按字段身份迁移内容，用户自行调整的列顺序和列名予以保留。

2026-10-08调整：柜型多选移至主查询区，选项为20GP、40HQ/HC、40NOR、45HQ/HC。45表示包含明确的45尺高柜信息，报价与适用限制在详情；主条目角位显示45标签。高级区保留来源群、舱位类型和日期，只有这些条件实际生效时显示高级角标。

**待审核**：显示来源群、发送人、消息时间与可核对原文；“已过”保持已过，不为了同组展示改写状态。风险条目给原因、下一步以及可回到原图的入口。失败反馈附近有可恢复动作，结果 Toast 不能代替具体字段错误。

待审核工具栏固定为两层：第一层只放 ID 查询与审核/校验状态，第二层只放数据类型、展示方式、结果数量及操作。类型和视图各自组成带短标签的分段控件；港群建议、刷新和批量放行靠结果操作侧排列。窄屏按完整控件组换行，不能让标签、选项和对应按钮分散到不同位置。

价舱管理沿用相同结构：第一层放 ID、状态、来源群和港口筛选，第二层放运价/舱位类型、卡片/条目视图、结果数量与刷新。两个航管页签的同类控件保持相同位置、尺寸和换行规则。

**运行中心**：健康/关注/风险三色仅对应带时间窗的真实监控判断；悬停解释阈值，图上始终显示人数/条数/比例及样本基数，图例与条色一致。新增群依据库中群条目与实际采集状态自适应，缺数据标“暂无样本”而不是 0% 健康。

**账号与成长**：首字头像不编码成功/失败；角色标签使用独立角色配色及文字，销售绿仅代表“销售”，不代表健康或成功。账号详情不设置独立“我的成长”卡片；用户名与小号角色标签同行，等级、循环胶囊位于下一行，XP 进度条紧跟胶囊下方。循环配色独立于账号角色：初始纯色、普通循环扁平渐变、最高阶金色立体边框，以便同一账号的成长阶段可直接辨认。账号液位固定跟随同一等级进度，不提供关闭开关；进度条 `role="progressbar"` 带当前值，数值文案解释距离下一级或下一循环。账号偏好修改有明确保存反馈，离开再进入仍可见，安全信息与默认范围分区。

成长节奏使用循环内线性成本：每循环 50 级，单级从 12 XP 增至 30 XP，整循环 1026 XP。进度文案优先显示“本级已获 / 本级所需”，累计经验与本循环进度放入提示；经验来源和每日上限由服务端规则返回，前端不得自行写死奖励或通过视觉暗示经验会改变权限。

成长反馈使用独立右上浮层，不挤占业务成功 Toast：显示本次 XP、今日累计、每日上限和距离下一级；升级时标题变为“等级提升”，跨循环时显示新循环。浮层颜色跟随账号角色，点击进入账号页，并同步顶栏液位、等级胶囊和进度条。普通反馈约 4 秒自动退场，不使用彩纸、连续抖动或全屏遮罩；窄屏不贴边，`prefers-reduced-motion` 下取消非必要动画。所有数值以响应中的 `growth_award` 为准，不根据按钮点击或条目数量猜算。

## 交互与无障碍验收

- 默认、hover、focus-visible、active、disabled、loading、error、success 是互不混淆的状态；不能仅 hover 才显露关键数据。键盘 Tab 应到达主操作、详情、弹层关闭与菜单项；焦点有清楚边界，弹层返回原触发处。
- 内部验收目标：正文与底色至少 4.5:1，大字与关键非文字边界至少 3:1；实际发布前以浏览器测量，`--ink-muted` 仅用于非关键辅助信息。按 [W3C WCAG 2.2 的对比度条款](https://www.w3.org/TR/WCAG22/#contrast-minimum) 和 [非文字对比度](https://www.w3.org/TR/WCAG22/#non-text-contrast) 检查。字体缩放到 200% 与 390px 窄屏不丢功能，系统减少动态效果时取消非必要动效。
- 数据表/看板有加载、空、错误三态；错误说明原因或可恢复动作。日期显示格式统一到分钟，未来生效、过期和未填不只靠背景色。复杂数据不靠不可读的 tooltip 承载全部解释。

## 落地规则与当前差距

- 新组件直接遵守本文；改旧组件时逐处迁移，禁止全局 `button`/`input` 重置伤及角色与审核语义。任何新增颜色先回答“它表示什么”，优先复用现有变量；新语义才在 `:root` 建变量与文档用例。避免在功能区再写硬编码绿/青绿。
- 2026-09-30 本次把个人资料的头像与成长标题归到品牌色，身份标签和经验条共用账号角色色；未宣称全站颜色统一。已知待治理：旧 `--accent` 仍是青绿色交互强调，部分选中筛选与焦点继续呈青绿；`profile-choice`、`profile-region-count` 的浅绿色选中仍是旧样式；健康、成功与低价共用绿色也需区分；多个局部硬编码颜色尚未集中。迁移需逐页看实际语义、对比度与角色视图，避免机械替换。
- 验收矩阵按销售/航管/管理员/登录 × 1280px/390px × 默认/加载/空/错误/成功状态逐项记录截图和可操作性。涉及动态权限和业务数据时要用有代表性的测试身份；单张首页图不能代表全角色通过。状态色、焦点、横向滚动、布局、字体、来源真实性由人工与自动检查共同确认。
- 页面原有统一组件：`btn-apply`/`btn-submit`/`btn-bulk`、`btn-ghost`/`btn-reset`、`ops-tabs`/`cat-tabs`、`sub-tabs`、`account-menu`/`box-menu`/`ac-pop`/原生 select、`toast`、`auth-card` 等。日期弹层沿菜单外框，单选 select 在支持的浏览器用 base-select，不支持时保留原生；多选列表不转换。公告只管理编辑器布局，按钮继承公共样式。

本文为单一项目规范入口；知识库只保存导航、决策及验证范围。生产变更应先留工作区检查点，针对受影响组件验证，确认后再更新本节状态。

报价标题位于表格顶部的深蓝合并行，REMARK位于各表底部浅色合并单元格，二者与字段区共用外框；界面操作中文，报价表及邮件内容英文。

报价表键盘导航（6.41.1）：左右键在当前行相邻编辑单元格间移动，上下键在同一列相邻行间移动；船司、POL、POD 联想候选打开时，上下键仍用于选择候选。REMARK 不参与导航，日期选择器保留自身键盘交互。

销售查询字段使用“船司”。运价查询默认并发检索公司运价，结果区对用户显示标题“内询单”；接口和内部任务仍使用 company rates 语义。内询单与钉钉群聊结果分区展示并可独立折叠；缺少起运港或目的港时，内询单分区说明所需条件。船司线上查价在查询栏中默认折叠，标题栏直接提供“展开查询”，展开后才显示 ETD、运输条款、重量和查询按钮；查询结果继续独立折叠，不与默认查询混为一项。

销售页不显示高级筛选入口。起运港/目的港按主数据、别名与港群规则匹配并默认展开港群，默认不混入消息原文/备注全文匹配。筛选栏提供“全局查询”勾选组件并注明“（附带消息原文查询）”，勾选后传 `global_query=1`，港口词才额外匹配原文和备注。

船公司线上查价表头（6.49.0）与公司运价、销售运价共用排序按钮视觉和 `aria-sort` 语义：承运人、起运港、目的港、ETD、船名/航次、ETA、海运费、单箱总价、获取时间均可排序；默认海运费从低到高，价格表头在升序与降序间切换，其他字段三态排序，空值始终置后，操作列不参与排序。
