# 字段治理与防护规范（field-governance-spec）

> 适用：`运价项目/Database` 人工维护台账（`manual_server.py` / `freight_manual.db`）。
> 一句话原则：**按字段的"性质/风险"分级设防，不搞一刀切引用完整性。** 允许自由文本的溯源字段保持宽松（只登记、可写入、不强制对齐）；真正错一次代价大 / 量大兜不住 / 改一处牵一片的关键字段，才上防护——且防护以**"不阻断录入、只体检报告"**为主。

## 1. 字段分级

| 档位 | 字段 | 处置 |
|---|---|---|
| **强约束（闸门）** | 起运港 / 目的港 / 船司 / 航线 | 已有：别名/中英/拼音/LOCODE 归一到主数据，命中不了 → `check_status=failed` 挡在待审核（核心匹配字段，脏值直接毁看板与分区，必须拦）。 |
| **数值/格式 CHECK** | 海运费 / 价格 / 箱量 / 目免 / 亏舱 / T-T航程 / 有效期起止 | 已有：SQLite CHECK 非负整数 + 有效期 ISO 日期格式；区间与越界进体检。 |
| **完整性核心** | `content_key` 指纹 / `status` / `supersedes` 超链 | 已有：判重 + 新增/更新自动留痕 + 追链不分叉；断裂进体检报告。 |
| **宽松溯源（本次）** | 来源群 / 发送人 | **不强制对齐**。写入即登记进字典库（见 §2），字典库可写入（人工/自动并存，带来源标记，见 §3）；业务里有、库里没有 → 体检只报告，绝不拦。 |
| **自由文本** | 备注 / 消息原文 / 船名航次 / 船期截关 / 有效期原始串 | 不归一、不校验，原样留存做溯源。 |

判据（何时给某字段升档到"强约束"）：三选一成立才升——① 错一次即污染下游（看板/分区/报价单）；② 取值是有限可枚举且人工维护得起；③ 历史脏值规模大到不治理不可用。来源群/发送人不满足（取值开放、天天变、强行对齐会大面积拒收、堵死 heartbeat/批量导入），故留在宽松档。

## 2. 写入即登记（覆盖全写入口，只补不覆盖）

任何**成功落到业务表**的记录，其 `来源群` / `发送人` 都要确保字典库里有对应条目——把"陌生值混进来毫无反应"变成"至少进库、可查可维护"。

- 落点（唯一事实源，避免各处重复）：
  - `push_with_review`：覆盖 **人工录入 `/api/push`** 与 **待审核放行 `approve_pending`（心跳/agent 走此）**；
  - `sync_rows`：覆盖 **批量导入 `/api/sync` / 整库快照导入 `/api/import`**。
- 规则：`name` 精确匹配（`strip` 后）判断存在与否；**库里已有 → 原样不动**（保护 `default_pol`/`owner`/`cid`/`note` 等人工维护项），**没有 → 新增**，`来源群→chat_groups`、`发送人→senders` 各自独立。空值跳过、不报错。
- 幂等：同批多条同群/同人只登记一次；重复放行不产生重复行。
- 新增了条目才 `invalidate_master()`，让录入端候选/归一索引跟上。
- **不加引用闸门**：`/api/pending` 暂存、`/api/validate` 预检、放行**都不会**因为"这个群库里没有"而判失败或拒绝——登记是副产物，不是前置条件。

## 3. 可观测：字典库来源标记

`chat_groups` / `senders` 各加 `source` 列：`manual`（人工录入/导入维护）| `auto`（系统"写入即登记"自动补的）。用途：看板"库管理"能一眼分辨哪些群/人是自动攒出来、还没人工补全默认港与归属的，便于二次治理。**仅标记，不参与任何过滤或拦截。** 迁移：`ALTER TABLE ... ADD COLUMN source TEXT DEFAULT 'manual'`，存量行回填 `manual`。

## 4. 不阻断式体检（`audit_all` 增 `integrity` 分类）

在原"标准化 violations"（核心字段是否命不中主数据）之外，新增 **`integrity` 引用完整性/健康度**清单，全部**只报告、不改数据、不拦录入**，在前端"全库体检"里分组呈现：

| 类别 | 判据（只扫当前生效行） |
|---|---|
| 来源群未入库 | 业务 `source_group` 非空且不在 `chat_groups` |
| 发送人未入库 | 业务 `sender` 非空且不在 `senders` |
| 港口不在主数据 | 业务 `pol`/`pod` 非空，既不是港口规范名也不是港群名（`Master` 索引外） |
| 同身份多条当前生效 | 同 `(pol,pod,carrier,container_type[,space_type])` 出现 >1 条当前生效 → 超链疑似断裂 |
| 已过期仍当前生效 | 当前生效且 `valid_to < 今天` |
| 价格为 0/空 | 当前生效但 `freight_usd`/`price_usd` 为空或 ≤0 |
| 价格离群（疑录入错） | 同 `(pod,carrier,container_type)` 当前生效 ≥3 条，取中位数 m，标记 `< 0.5m` 或 `> 2m` 的行 |

响应结构：`{ok, violations, count, integrity, integrity_count}`；`violations`/`count` 保持原语义向后兼容，`integrity` 为新列表，每项 `{type, kind, detail, content_keys?, pol?, pod?, carrier?}`。

## 5. 边界与非目标

- 不上 SQLite 硬外键、不加 NOT NULL FK 约束（阻断 + 需大迁移 + 与"业务先行/heartbeat 宽松录入"冲突）。
- 体检不自动修数据、不自动改价、不自动并账——只列给人看，人再决定放行/编辑/回库管理补全。
- 来源群/发送人永远允许写进来；本规范只是让它们"进得来、留痕、可回查"。

## 6. 主数据维护约定（字典自身）

字典烂了，闸门再严也只是把脏值挡在门外、好值也一起挡。本节立五条规矩（2026-09-12 体检后定）：

1. **规范名消歧**：跨国同名一律 `Name(XX)`（现状 7 行：`Caldera(CL)/(CR)`、`Cartagena(CO)/(ES)`、`Port Elizabeth(US)/(ZA)`、`Manzanillo(PA)`）；同一港的多种拼写取更常用者作规范名、另一写法进 `aliases`。**裸同名不消歧会被歧义规则丢弃——这是特性不是 bug**，宁可不归也不错归。
2. **`aliases` 只放"能唯一指向本行"的写法**。禁止放：区域/航线词（`地中海`、`南美西`、`加勒比`）、国家码（`cn`、`br`）、别的港名/船司名。理由：这类词必然指向几十个实体，索引里被整条丢弃，**写了不生效，还制造"我登记过了"的错觉**（本轮清掉 338 条这种死键）。区域归属走 `routes.region` 与港群，国家走 `country` 列（`country` 已不再参与匹配）。
3. **港群成员必须是 `ports.name` 的精确值**，`master_save` 已强制校验、命中不了直接拒（存量由 `master_health` 报告）。缘由：成员写错一个后缀，"查成员港带出群价"的双向展开就静默断链，且不会报任何错。
4. **停用不删行**：长尾港要退出匹配就置 `active=0`（`Master` 只读 `active=1`），随时可恢复；批量停用前先出清单人工勾（见 `主数据-auto长尾收口候选-*.md`）。
5. **agent 自动补的船司带溯源**：`ensure_carrier` 只给"形态像船司缩写"的未知 token 建主键，`note` 必含 `auto：待人工复核＋来源群/发送人/消息ID/原文`；定期复核，发现是别家笔误就合并或置 `active=0`。港口/航线**不开放**自动新增，仍走人工。

字典自身的洞由 `/api/audit` 的 **`master_health`** 每次自动查这七类：港群成员断链、各表歧义死别名、规范名折叠重复、括号不闭合坏行、`locode_ref` 缺失、`active` 未收口、`senders` 主键嵌电话。只报告、不阻断。

## 验收

- 副本库回归：经 `/api/push` 与 `approve` 各放行一条带全新群/人的记录 → 两库补齐且 `source='auto'`；人工在库管理新增的 → `source='manual'`；重复群/人不二次登记、不覆盖已维护项。
- 体检：造一条过期仍生效 + 一条孤儿港口 + 一条价格离群 → `integrity` 分别报出对应类别，且该记录照常入库、放行不被拦。
- 前端：库管理群聊库列表显示"系统登记/人工维护"标记；"全库体检"分别呈现标准化不达标与健康度两组。
