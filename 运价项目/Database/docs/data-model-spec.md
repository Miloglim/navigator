# 数据模型定稿（data-model-spec）

## 运价币种（2026-10-23）

`freight_items.currency` 保存运价金额的三位 ISO 风格币种代码，默认和存量兼容值为 `USD`。历史 `海运费USD` / `price_usd` 字段名继续保留以兼容接口与旧数据，但金额币种以 `currency` 为准，不再从字段名推定美元。EUR/CNY 等非 USD 记录保存原金额，不做换汇；`海运费USD` 在契约中作为兼容金额键使用。待审核 payload 同步使用 `币种`，SQLite/PostgreSQL 启动迁移为旧记录回填 USD。

## 用户留言板（6.51.2，开发端专属）

`message_board_posts`独立保存开发端用户留言：`id`为文本主键，`user_id`和`author_name`来自发布时会话快照，`content`为最多1000字纯文本，`created_at`为北京时间字符串。`created_at`及`user_id`建索引，按时间倒序分页。正式端默认关闭接口和页签；开发端需显式开启。留言不属于运价、舱位、公告、通知或主数据。

> 适用：`运价项目/Database`（台账）+ `Skill/freight-rate-heartbeat`（采集）。
> 定稿时间：2026-09-12，依据：本轮逐条确认 + 2850 条群聊语料取证。
> 这份文档只回答一件事：**一个名字从群里到看板上，每一层是什么、谁负责、在哪张表。**

## 1. 四层名词，一句话各管一段

| 层 | 是什么 | 管什么 | 在哪 |
|---|---|---|---|
| **实体** | 一个真实的港 / 船司 / 航线 / 群 | 存在性 | `ports` / `carriers` / `routes` / `port_groups` |
| **规范名** | 实体的唯一代号（`Santos`、`MSC`、`欧基港`、`MEX`） | **显示** + 业务表里存的值 | 各表主键列 |
| **识别名** | 该实体的各种叫法（`桑托斯`、`BRSSZ`、`达飞`、`CMA CGM`） | **匹配入口**：把传入 JSON 里的任意写法折叠命中规范名 | 同表 `aliases` / `name_cn` / `locode_ref` |
| **港群** | 一群港共用一个名字（`MEX` = `Manzanillo` + `Lázaro Cárdenas`） | **标准化不同航管的说话方式**，一条报价覆盖一片港 | `port_groups` |

```
   群里写的              匹配（识别名）            库里存的（规范名）        看板上显示的
  ─────────             ─────────────            ────────────────         ─────────────
  桑托斯      ┐
  SANTOS      ├─ fold() ─▶ port_idx ─▶ "Santos"  ─▶ pod="Santos"   ─▶ Santos
  BRSSZ       ┘                                  （单港）
  NBE / 北巴  ──── 群作用域别名 ──▶ "NEB" ──────▶ pod="NEB"        ─▶ 北巴（悬停看成员）
  Pecém（查）◀────── 双向展开 ──────────────────────┘ 成员港价一起出来
```

**关键性质**：业务表里**永远只有规范名**；识别名是入口不是存储值；港群名本身也是规范名的一种（可以直接当 `pod` 存）。

## 2. 规范名 = 唯一显示名，但**界面上不带国家括号**

按业务实际（90% 场景销售只看标准英文起运/目的港，且主要动作是点开详情看原文）：

- 界面显示一律用**裸英文名**：`Cartagena`、`Caldera`、`Manzanillo`，**不显示 `(CO)` `(CR)` `(PA)` 这类后缀**。
- 后缀只活在数据层，作用是让跨国同名各占一个主键、互不覆盖。
- 到底是哪一个，**看详情里的原文**——原文是逐字存的，`巴拿马科隆`、`多米尼加 CAUCEDO` 这类上下文自带答案。
- 剩下约 10% 的中文查询场景，靠人工维护 `name_cn` 逐步补齐（现在 817/1190 行为空），**不做自动翻译、不做相似度匹配**。

> 落地要求：前端渲染 `pod`/`pol` 时过一次 `display(name)`（剥掉尾部 `(XX)`），
> 悬停 tooltip 显示国家与 LOCODE；数据层与接口返回值**不变**。

## 3. 识别名带**作用域**：全局 + 按群

同一个缩写在哪儿是一个意思，取决于**列**和**来源群**。实测证据：`NB` 在语料里出现 98 次，**全部是"宁波"（起运港）**，跟"北巴"没有任何关系；而 `NB` 现在正是 `Ningbo` 的别名。

所以规则是：

```
匹配顺序（同一列内）：
  1) 本群专属别名   ← 新：alias_scope(alias, group, kind, target)
  2) 全局别名       ← 现：ports.aliases / carriers.aliases / routes.aliases
  3) 港群名 / 港群标签
  4) 规范名本身
折叠口径唯一：manualdb.fold()（去音标、大小写、. , ' - ( )，保留空格）
歧义处理不变：一个键指向 ≥2 个实体 ⇒ 整条丢弃，宁可不归也不错归
```

- 别名里**禁止**放：别的实体的属性（国家名、港名当航线别名）、区域词、任何指向不唯一的写法。上一轮清掉的 338 条就是这类。
- 群专属别名放 `alias_scope`，不放全局 `aliases`——这样"A 群的 X 指甲、B 群的 X 指乙"才表达得出来。
- 前端配合：**群聊选择组件**（销售端筛选栏下方那排群快捷筛选 / 航管端来源群下拉）决定当前作用域，切换群时候选列表跟着变。

## 4. 航线是港口的**子属性**，族是航线的父

```
ports.name ──┬── route（子线，可多值：Balboa = 中美洲,加勒比）
             │        ▲
             │        └── 新增列：航线跟着港走，不跟着报价说话
             ▼
        routes.name ──── routes.region（族：美加线/欧地线/拉美线/澳新线/亚洲线/非洲线）
```

- **港口**决定航线；**报价记录**上的 `route` 是派生结果，不再由人填。
- 族**不存**在港口上，永远从 `routes.region` 现取（能算出来就别存）。
- 一个港可以挂多条子线（运河/海峡类港口天然跨线：`Balboa`、`Colón`、`Port Said`、`Aqaba`），所以 `ports.route` 允许逗号多值。
- 派生种子已有：`ports.source` 里 330 行带区域 token（地中海 41、南美西 40、南美东 31、加勒比 30、北欧 26、美东 26、澳新 22、北巴 8…），可一次性转成 `ports.route`，其余人工补。
- 闸门策略：`pod` 能派生出航线就**覆盖**传入值；派生不出来则留空；传入值与派生值冲突 → 打回提示，不静默改。

## 5. 港群：agent 只提候选，人工才改字典

港群是放大器——成员加错一个，整群价被错误展开，污染面远大于一条记录填错。因此：

- **agent 不得直接写 `port_groups`**。新增待审类型 `group_suggestion`：agent 提交"我建议 `NBE` → {Belem, Manaus, Itaqui}，出处=某群某消息"，人工在待审页放行才落字典。
- 人工保存港群时，成员**必须逐字命中 `ports.name`**（`master_save` 已强制，报错即拒），存量断链由 `/api/audit` 的 `master_health` 报告。
- 存值规则不变：命中港群 ⇒ 存**群名一条**，不拆成员；查询 ⇒ **双向展开**（筛成员港带出群价，筛群名带出成员价，非成员不串）。

## 6. 一条记录的完整路径

```
钉钉群消息 ──dws──▶ 逐字落盘 ──▶ 模板直出 / LLM 补判
                                      │  产出中文字段 JSON（识别名原样）
                                      ▼
                        POST /api/pending ──▶ expand_cn 多维展开
                        （船司多值拆 N 条 · 柜型逐档配价 · 群名一条不拆）
                                      ▼
                        validate_record 闸门：识别名→规范名 · 四档柜型 · 十一档舱位类型
                        · 占位符视为空 · 说明词挡下 · 未知船司自动补主键(带溯源)
                                      ▼
                        pending_records（待审，人工放行才继续）
                                      ▼
                        freight_rates / space_records（只存规范名 + 逐字原文 + 原图引用）
                                      ▼
                        看板：折叠视图现算"当前生效" · 港群双向展开 · 航线由 pod 派生
```

**"进待审 ≠ 入库"**，"显示用裸英文名 ≠ 数据层去掉消歧后缀"，"航线跟着港走 ≠ 人往记录上填航线"。

## 7. 表职责与本轮定稿要动的点

| 表 | 职责 | 本轮定稿的变更 |
|---|---|---|
| `ports` | 港口实体 + 识别名 | **加 `route` 列**（子线，可多值）；`country`/`city_pinyin` 退出匹配（已做）；`name_en` 与 `name` 1179/1190 同值 → 待删（A 类） |
| `port_groups` | 港群 | 成员保存强校验（已做）；`specials` 保留备用 |
| `routes` | 航线子线 + 族 | 两级结构已定稿：6 族 30 子线（`region` 存族，零 DDL）；别名禁放国家名/港名（已清理） |
| `carriers` | 船司 | 未知船司自动补主键 + `auto：待人工复核` 溯源（已做） |
| `pending_records` | 闸门 | **新增 `kind=group_suggestion`**（agent 提港群候选） |
| `alias_scope`（新） | 群作用域别名 | **新建**：`alias, group, kind(pol/pod/carrier/route), target, note` |
| `freight_rates` / `space_records` | 业务事实 | 结构不变；`route` 改为派生覆盖；`image_url`/`image_file` 双列待合并（A 类） |
| `chat_groups` / `senders` / `operators` | 配置与权限 | `chat_groups.region/owner` 空转待删；`operators` 启用还是摘掉**待你定** |
