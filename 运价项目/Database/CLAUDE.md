
- 公司网关Token身份、钉钉ID与业务header.xUserId不是同一概念。钉钉ID误填xUserId时，普通运价可能仍可读，而实时创建返回success=true/task=[]；不能以普通查价成功认定业务身份正确，也不能把空任务说成无报价。实时查价ETD应单独选择，不能借用报价有效期。
- 本地locode_ref和别名不是已核实的外部身份。Shanghai历史代码CNSHG实际指向SHANHAIGUAN；自动港口匹配必须用同一候选的公司编号和规范港名或非代码别名共同确权，不能把查询代码与公司回显代码一致当作匹配成功。错误代码应回退名称查找，仍无法确认则拒绝；Sokhna Port已改为规范名Sokhna，旧写法只留别名。
- 公司业务用户ID可能超过32位整数范围：跨库映射标识使用BIGINT，不能用SQLite测试通过推断PostgreSQL的INTEGER足够。查询签名也须显式按列名取值，PostgreSQL兼容行迭代得到键名而SQLite得到值。
- 待审API会将分页上限压到500，不能以“返回不足请求limit”推断已读完；必须按total连续读取并拒绝分页总数漂移/重叠，否则整组复核会漏行。主动复核修后内容指纹必须同时结案，否则自己修改产生新版本会被再次领取；所有既有edit_log保护，不能靠passed推断可覆盖。
- 港群别名写入必须按正式港群名校验：`agent_master_ensure` 不能只调用 `lookup_port`（它只查普通港口/别名），否则 `NEB/ECSA` 会被错误拒绝；港群目标需直接在 `group_by_name` 中校验 kind。
- 登录成功数、有效会话数和经验流水都不能代替日活：前者会受重复登录影响，会话可跨天，经验又有每日上限。产品活跃度必须从服务端绑定身份和时间的行为事件派生；自动加载与用户主动查询要分开，否则热门港口和查询次数会被初始化请求污染。
- `semantic_issues` 和 Markdown 阻塞报告只在采集运行态可见，航管看不到。无结构化报价但有源消息证据时，先通过 `/api/review-issues` 保存待核问题，再允许流程前进；不能造空报价，也不能把本地报告当成前端已交付。旧服务须升级，历史回填须核对实际写入数。
- 缺OCR是Agent尚未完成的工作，不是留给航管的业务问题。必须继续识读、结合同消息正文及群知识生成完整候选；真实歧义应明确指出原图位置和缺失信息。完成后分页核实待审回执，使用agent settlement关闭旧问题；仅生成本地JSON或标记已处理不能替代报价入待审。
- 同源补漏不能仅按港口/柜型匹配覆盖：一张舱位图中不同价格或SI/CY节点可能属于不同报价。未编辑行须匹配完整提交指纹才视为覆盖；人工编辑行仍保留审计和原内容，不能用回填覆盖。每批新增行必须进入同一指纹索引，重复执行不新增重复报价。
- 图片缓存写入不代表逐图判定已完成；历史恢复必须核对每源read=true、完整终态、完全一致的media集合后才提交，防止读图Agent的临时缓存先入库。旧候选替代只归档本轮未编辑awaiting Agent行，先快照，再保留原证据的驳回日志。
- expand_cn必须保留目的地CY/ICD/by rail标记再交校验。提前按港口别名归一会吞掉内陆交付语义，使预检失败的铁路点暂存成passed海港；别名匹配不能抹掉业务限制。
- 正式港名自带逗号（Freeport, Grand Bahama）时，先确认它是name_idx中的完整规范名，不能按多值串拆开；别名指向多个港口才允许拆分。
- 群显示名和知识目录不必同名：知识写入必须走chat_sources.json的spec_dir；自行把斜杠换加号会在有空格的ONE群丢失沉淀，不能把DB写入成功冒充knowledge_saved。
- 报价发布人页面不能在每次读取或决定后重解码全部 DWS 历史文件；证据解析按文件指纹缓存，名单仍须每次读取。缓存失效必须覆盖原始消息、归档和拉取回执，不能只看目录时间。

- Prospector Bearer 不继承同请求管理员 cookie 或采集器头的写能力；先识别 Bearer，再走固定只读白名单。安全失效须绑定 account_security.revision，单查 active/密码会让撤销后重新启用的旧设备凭据复活。刷新与退出须锁设备授权行，PostgreSQL 仅更新旧 token 行可能漏撤销并发插入的新 token。
- 同一次 Prospector 运价/舱位、分页和重试共用 query_id；统计按服务端 user_id+query_id 去重，不能让客户端下划线字段伪造来源或身份。旧网页主动查询语义保持原样。
- Prospector 不能用柜型字面LIKE代替既有柜型契约：AI/UI 的40HQ必须命中历史40HC及规范40HQ/HC，NOR不能混为高柜。复用ctype_list与ctype筛选，并覆盖组合柜型测试。主动查询用terms表达目的地时，统计须保存有界解码后的terms等真实筛选项；只记page/limit会产生无法追溯目的地的假留痕。查看过期报价仍须排除已被覆盖行。

- Prospector 私有 LAN HTTP 是用户明确批准的部署方式，不可只修改客户端：服务端需同时放行实际私有 peer 与字面量私有 Host，保留公网拒绝和代理头不可信；磁盘修改后通过 watchdog 重载进程并检查 PKCE 授权页面 200。

- Prospector 桌面筛选与网页不同源会跑偏：候选复用 Navigator 主数据，桌面 match=web 复用网页精准过滤，不用目的港 terms 跨字段 LIKE，不偷偷加今天有效期；AI 自由词筛选保留原路径。
# 公司列表汇总陷阱（2026-10-14）

船司实时轮询是分船司陆续返回；检查all(已返回行终态)不代表全部请求船司完成。必须以请求carrierIds为预期集合逐港口组合核对，累积终态响应；超时保留已取报价并标出缺失，不得悄悄丢弃迟到船司后报complete。

公司运价单日筛选是当天及以后，仅传valid_from；不能附加当天valid_to截断未来报价，也不能因存在valid_from就跳过班期补全。6.34.4实测后实时ETD同样改为所选日及以后、只传validFrom；前端必须逐条展示船司result数组，不按船司或相同价格合并船期。

公司列表的一行可能汇总多个 `schedule_list` 产品，但 `product_price` 仅属于代表产品。不能将代表价复制给其他产品，也不能从备注猜价格；按源日期补查并核对产品编号，缺失明确标记部分完成。公共结果容器必须同时受当前页签和来源开关控制，异步回包不得重新打开其他页的结果。


- SQLite `PRAGMA data_version` 只在连接内有意义，不能单独作为跨数据库缓存键；内存库和临时库必须加入连接或路径命名空间。

- 中心鉴权 HTTP 401/403 是账号或产品权限拒绝，网络超时/连接错误才是服务不可用；错误分类要保留给用户可行动的提示。
